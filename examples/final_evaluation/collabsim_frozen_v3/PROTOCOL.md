# 当前 CollabSim 评测：v3，仅 ShapeFactory

Hidden Profile 已退出当前评测。v1/v2 和历史运行保留作来源记录，不再使用旧入口启动正式测试。

入口：`python -m examples.final_evaluation.collabsim_frozen_v3`，参数与 v2 相同；`--verify` 离线验收；不加 `--run` 只生成四局配置。

ShapeFactory 有效环境配置与 v2 完全一致：3 人、3 种专长、每人 1 个非专长订单，forward/reverse 两个供货循环 × private/dashboard。原生规则、提示、persona、解析、生产上限 3、经济参数、900 秒真实时间、10 秒触发、30 秒生产延迟、probe 和停止规则均不变。

同一模型控制全部席位。温度 0，seed 42；服务统一 98304 上下文、4096 输出预算、后端、精度和 batch-invariant。入口只记录服务要求，不认证实际配置；必须归档启动命令。计时与异步完成顺序仍影响行动机会，batch-invariant 不等于完整轨迹确定。

## 可解性和解释边界

每人有 200，非专长自给 1 件成本 40、履约奖励 60，可得 220；各生产 1 件专长产品并完成环形交易，团队总余额 735、人均 245。不存在预算、产能或订单不可解问题。原生经济执行器回放已验证这两个终态；它不是实时控制器或模型的成功保证。

三人供货环中购买对象与出售对象不同，明显比双人互供复杂；不应把两者合并平均，也不能把旧两人 5/8 与三人 1/12 解释成同难度能力下降。四局只有两种循环方向和两种可见性，不是四个独立随机问题；可作为小规模外部迁移诊断，不足以单独支撑广泛泛化结论。

## 计分

并列报告订单完成数/12、三方均完成局数/4、人均最终余额，附逐条件结果。不以消息量或成交次数直接认定更强合作。

原生 summary.completed_trades 包含拒绝/取消报价，禁止将其当实际成交数；真实成交以 trade_offer_responded 且 response_type=accept 为准。action_validated 只表示通过检查，不能代替生产、成交和履约事件。旧原生汇总字段保留供追溯。

所有局均报告；退出 0 或 COMPLETE 不是无内部错误证明。检查 HTTP、上下文、probe 错误；格式/规则/状态误读属于模型失败。900 秒不是进程墙钟上限。报告调用数和耗时。此版不通过缩短时限或降低难度来抬高结果。
