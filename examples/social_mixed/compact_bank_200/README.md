# 固定200个训练母题

当前 reasoning 配方的 O/C/D 入口使用本库；SP不变。每个母题保留O/B/Pplus三个视图，共600条任务。验证仍由原 paired_bank_v2 的独立验证入口加载，不取本库作验证。没有启动训练。

基础60、中间60、复杂80，均按同母题三个视图的最高结构难度划分；这是覆盖配额，不是已验证的最优课程。148个旧母题、52个新简单母题。按B证据与标签、P操作类型与跨度、来源结构覆盖选题，并抑制同family重复；没有按模型成绩筛选。保留8个update、13个maintain、35个must-change关系。详细覆盖见summary.json。

P全部具有positive和negative动作，masked规则不变。新场景P跨度使用明确标记的结构proxy；不冒充旧库已审计的终局transition类别。固定continuation限制不变。

D仍为O/B/P各4组，每组8个回答，损失各1/3。曝光优先级仍是先最少累计曝光、再结构难度；关系不能跳过曝光底线。离线模拟200次更新：第50/100/150/200次后，每个视图的每道题恰好曝光1/2/3/4次。O沿用原token边界，不强行和D做相同step数；比较仍需报告实际tokens及曝光。

本库已接入实际训练入口，并用manifest记录选择和来源；旧大库checkpoint不能无提示恢复进新池。未修改学习率、温度、max_steps、总token预算、验证频率或优化器。保留原任务training_ready字段作为上游认证状态，不把未实测的简单层宣称为已通过GPU/可学习性验收。

复算与验证：

```sh
python -m training.social_mixed.compact_bank
python -m unittest training.social_mixed.test_compact_bank -q
```

不另跑Q0学习探测。真实可学习性和持续保持仍需在正式训练日志中检验，CPU检查不构成性能保证。

## 操作衔接修订（compact-200-operations-v2）

选题先为关联操作预留最多120个母题的位置，再补足结构覆盖；不增加总量。最终165个母题至少有一个入选关联端点。关联不是独立样本数量，也不是新增奖励：

- 109个先验对照：归一化后的其他源输入完全相同，仅background_prior不同。
- 35个调查结果对照：其他源输入完全相同，仅private_results不同。
- 8个判断更新、13个判断保持、35个必须改变行动关系，沿用原认证。
- 38个同场景操作联系：相同目标几何、自身及公开偏好、先验、伙伴策略，连接不同证据／规划阶段。历史及剩余轮次可能同时变化，明确不称为单因素难度递增。

每题另记operation_curriculum：B区分直接结果、先验与公开约束、单行为排除、单行为不确定性、多事件；P区分已知／不确定belief以及终局回应／最后提案／后续决策；O结合证据与行动跨度。最后一次提案仍有伙伴回应，不冒充直接终局动作。

所有题文、teacher和P评分原样继承已核验来源；此次改变的是200题的组成与关联记录，不是新造标签。关系不自动成为联合loss，也不把模型B预测输入P。曝光仍保持每视图每50步完整轮转，不为配对牺牲重复覆盖。没有改变训练排序或额外强制这些新对照同batch。

这比单纯按结构难度抽题多了可审查的操作联系，但尚未补齐“从目标独立到共享承诺、从少目标到多目标”的严格单因素梯度；同场景关联不能代替这项认证。真实可学习性也没有实测。不能宣称已经复现旧P持续学习机制。

operation_links.jsonl包含全部关联及认证范围；operation_examples.json提供各类关联的两侧请求与标签，可逐题复查。

## 最终训练内验证与保存

reasoning O/C/D/SP只验证固定静态O/B/P面板，temperature=0。CalBench与self-play交互验证均关闭。保留step-0基线；此后每完成20次更新验证并保存checkpoint，正常结束时补一次最终验证/保存，提前停止保留恢复保存。目录沿用零基编号，例如20次更新对应checkpoint-19，验证为step-20.json。

BEST按静态O的parent-macro正确率选择，同分保留较早结果；B/P为诊断指标，P仍报告masked覆盖。不会再读取CalBench分数选择checkpoint。checkpoint保留数量仍由原有keep-checkpoints控制（默认1，仅保留最新完整恢复点，不额外保留BEST权重），每20步保存不等于永久保留全部历史文件。旧验证选择版本不允许静默继承比较。
