# D24-v1三人伙伴选择增补

原24题保持原样。新增8个O/P视图，来自4个场景、2种物理结构；不是8个独立结构。不修改现有O/C启动入口，尚未提交训练。

## 场景

自己想完成两个目标：一个需要伙伴1的承诺，另一个需要伙伴2的承诺。只剩自己一次提议机会，两位伙伴均可被合法邀请，且若接受都能帮助实现目标。

- shared_self：两个目标复用自己的同一个承诺，重点是选择伙伴。
- distinct_self：两个目标需要自己的不同承诺，需同时选择对象和承诺。

每种结构有两种偏好条件。条件一：两位伙伴都want目标0、avoid目标1，因此应找伙伴1完成目标0；条件二把两目标偏好反转，因此应找伙伴2完成目标1。不是单纯改名或交换编号；目标/行动/席位不变，偏好变化使接受行为与最优对象变化。

三人都有正偏好；两位伙伴均在目标要求中，不再是无关的第三人。只有2个目标、1个有效剩余提议回合、每人每次至多新增1个承诺。最优行动唯一，伙伴错误会被拒绝；不是复杂长程规划。

## O/P

O给公开偏好、原生当前状态和两个被要求PASS的准备事件；无需从不确定行为推断偏好。这是基础伙伴选择题，不声称覆盖belief形成。
P只给当前状态、自己偏好、规则和伙伴定性belief（单值set/favored），不提供历史或数值联合posterior。
原24题中的旧P完全不变。因此这是保留旧P并增加简单定性P视图的增补，不是整个P库已统一接口。充分信息下新O/P接近，主要检查伙伴选择，不用于证明B分解的价值。

## 验证

`python -m examples.social_mixed.micro24_v1_partner_choice_v1.build`

调用BENAC原生合法动作、状态转换及终局goal_satisfaction；穷举每个提议及接受/拒绝结果。伙伴先最大化自身效用，只在响应平手时最大化他人效用；不调用旧partner kernel，不做depth=2截断估值。两位伙伴在强制ACCEPT下都有正的己方目标贡献。两种偏好条件的最优伙伴集合不相交。

逐个动作调用现有训练reward，确认与终局最优集合一致。P最优与非最优己方价值差为1，故0.1容差不改变接受集合。请求使用现有渲染器，保留解释后tool call。所有场景均为新train来源，未使用外部测试题。

尚未进行真实Q0采样、tokenizer长度预检或GPU训练。不能宣称新题已经显示学习信号；简单度是结构设计，非实测通过率。
