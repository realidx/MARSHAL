# 游戏、标签与训练流程重新审计计划

2026-10-21，按用户最新计划重新审视设计。本文是工作计划和待决事项，
不是新的可训练版本，也不代表以下候选定义和参数已经确定。

研究目标：比较game slices与完整self-play的训练效率，不设计新的GRPO方法。
后续按以下顺序推进；每步的设计结论、实现、验证和实际运行分别记录。

**最新确认以[节点Q/S/D设计v1](versions/node_qsd_design_v1_20261021/DESIGN.md)为准：**
双边OFFER；从当前节点到terminal；S逐条遗漏本人调查答案或公共历史信息，
公开偏好/规则/目标/自身偏好/当前承诺状态保留。节点价值必须结合指定模型实测D，
不以Q或S单独决定。下文“当前代码”是旧实现对照，不能作为新定义。

## 用户进一步澄清：参数化游戏与完整信息来源

玩家数、目标数、轮数、公开/私有偏好结构、调查额度和报价额度都是设计变量；
现有2/3人、一次调查等只属于旧实验限制，不能当作一般游戏的定义。
其中生产调查实现目前仍以布尔值记录每人一次，尚未支持任意额度；参数化属于后续实现。
新限制应同时考虑计算可行性、小模型任务难度，以及轮数/调查/报价之间的策略取舍，
不按某个变量孤立决定，也不沿用求解容易所形成的旧配额。

S的审计范围包括调查私有答案，以及调查行为/目标、PASS、OFFER、ACCEPT/REJECT对
其他观察者传递的信息。每种信号均须指定观察者、先验、策略模型和决策时点；
公开行动不必然提供信息，自己的选择也不是自己收到的新外部证据。
既有query与public-history指标只覆盖各自限定通道，不能直接称为完整信息价值。
同时评估非全树遍历的solver候选，区分近似策略搜索、均衡认证与Q/S求值的不同保证。
以上记录审计范围，未确定新的参数、S公式或solver，未更改生产配置。

## 1. 逐项检查游戏、题库筛选与solver标签

每一项都核对“预期规则—实际代码—标签计算—题面披露”，不能仅核对prompt。

| 审计项 | 必须回答的问题 |
|---|---|
| 目标与效用 | want/avoid、linear/binary、目标完成及承诺如何产生终局效用？是否有退化或重复目标？ |
| 行动与状态 | OFFER/PASS/INVESTIGATE/ACCEPT/REJECT何时合法、消耗什么、如何推进？接受的承诺与pending offer是否区分？ |
| 时间结构 | proposal轮数与实际玩家决策数如何对应？调查后是否有利用答案的机会？每个玩家是否有再次提案的机会？ |
| 信息 | 自己偏好、公开偏好、累计调查答案、公共历史和联合先验是否一致？允许哪些行为推断？ |
| 理性规范 | proposal自身目标与response自身优先、平局帮助其他玩家的规则如何统一实现和认证？ |
| solver | 求解到哪里、所有玩家如何行动、认证保证什么？off-path信息集、零概率分支、数值平局如何处理？ |
| 父游戏生成 | 人数、轮数、类型支持、目标结构与生成概率如何选择？求解失败是否导致系统性偏差？ |
| slice筛选 | 入口分布、k、可达质量、C/S门槛、保护规则、重复限制各自的目的是什么？ |
| 数据划分 | 是否按父游戏或结构隔离？验证/测试是否含真实信息决策？哪些历史结果已经查看？ |

已确认的审计起点：

- 原100父游戏为30个双人两轮、20个双人一轮、50个三人一轮。
  “至少30个多轮”是当时操作目标，不是用户确定的配额，也没有比例最优的研究证据。
  见[生成配置](../../new/local_data/strategic_slices_oracle_consistent_search_v2/config.json)。
  原100保留为历史诊断池；新正式题库的分布、数量与覆盖要求待讨论，不默认继承旧配额。
- 当前参考策略有response-only social tie，但slice求值、正确动作和训练reward仍是own-only。
  见[状态与评分核对](PROMPT_PROTOCOL_REVIEW_20261021.md)。这不是仅修改prompt可以修复的问题。
- 原验证/测试缺强query信息阳性覆盖；family并未完全隔离，历史test已在base D分析中被查看。
  见[配置对照第8—9节](PIPELINE_CONFIG_COMPARISON_20261017.md)。

交付：规则清单、实际实现对照、退化/反例、solver保证边界和题库覆盖方案。
先讨论这些结果，再确定新正式游戏与数据合同。

## 2. 修改并验证OFFER代价

已有用户方向：提出OFFER立即消耗个人报价额度，无论接受还是拒绝均不返还；
调查机制先保持原样，dependent preference暂缓。
额度1已有独立研究实现，但尚未成为生产默认；新游戏的额度与轮数应联合确定。

既有证据：原100中70个单轮局的额度1约束冗余；其余30局29个新profile认证通过、
1个未认证。见[整批结果](OFFER_QUOTA_ORIGINAL_POOL_RESULTS_20261021.md)。
这支持继续研究该机制，不证明新题库分布或额度参数已经合适。

验证需包含：调查严格有益、无需调查直接报价、调查浪费机会等不同情形；
允许不同题的最优行动不同。不能以“每题都应调查”为成功标准。

## 3. 讨论Q、S的计算与题目设计

先统一符号。当前代码的Q是入口行动价值，不是筛选用的C_span；
若用户所指Q是其他题目质量量，应另行定义，不能直接混用。

- 当前Q：给定入口信息集/belief、固定reference、剩余k个focal决策，
  首步选a，其后窗口内按自身效用最优contingent policy行动，窗口外reference继续到终局。
  见[values.py](../../training/strategic_slices/values.py)。它不是“全员因这次偏离重新求均衡”的值。
- 当前query S：在答案出现前的同一belief、同一物理树、相同对手及窗口外策略下，
  允许与不允许使用指定调查答案的最优策略价值差。
  见[masked_answer_value](../../new/benac_slice_pilot/metrics.py)。
  entry-private、future-public等其他通道分别审计，不能自动相加或称为同一个S。
- 信息能影响决策、答案本身有价值、选择调查优于直接报价，是不同判断。
  S为正不自动证明INVESTIGATE是当前最优行动；Q存在差距也不保证模型采样能产生组内差异。

新定义已确定从当前decision point优化至terminal，并以当前真实信息评价遗漏策略的损失，
不采用事前信息价值替代。仅逐条遗漏调查答案或公共历史信息，保留基础游戏信息。
Q、S用于解释节点属性，必须结合目标模型实测D判断训练意义。
待定：完整response平局目标下的Q如何表示、后续并列策略如何选、S应衡量自身效用还是
完整规则的决策影响、信息单元及遗漏后的策略约束。
不能用一个任意加权标量悄悄替代自身效用优先的规则。

交付：形式定义、可手算小例、独立枚举核验，以及它们对应的题型覆盖与筛选条件。

## 4. 规则和标签确定后修改prompt

沿用可读题面和具名工具；所有状态完整披露做决策所需事实，累计私有答案持续出现。
规则、工具、环境、正确动作和奖励必须一致。导出实际request生成的完整messages/tools，
逐状态审阅；旧prompt与已关闭快照保留原身份。

## 5. 在新合同下重测D并确定训练题目

先冻结游戏、reference、候选、split、prompt和模型身份，再测D。
记录采样参数、失败、完成率和不确定性；不把旧prompt D作为新prompt测量。
仅使用训练侧D选训练题，验证/测试承担各自的评估职责。
不能根据新test结果反复修改题目而仍称其为未查看测试集。

## 6. 对照既有failure pattern修复并验收训练pipeline

历史v6证据见[日志审计](../../new/terminal_node_v6_training_960070/review_20261017/README.md)：
总体验证改善与信息题失败同时存在；后期同动作塌缩、有效组稀少、解释输出减少需要分别解释。

逐项核验：题面/工具是否诱发错误，信息是否可利用，标签是否一致，组内样本是否可比，
连续reward差异是否实际被采到，关键行动是否失去采样支持，解释指令是否有效，
题目曝光与更新密度是否过高，验证/保存是否过频，以及采样/求值/日志是否成为效率瓶颈。
先区分设计、标签、接口、探索和工程问题，再选择有证据支持的修复；
不默认引入新GRPO变体或一次同时改多项超参。

最终验收还应包含匹配的完整SP训练臂、共同父游戏分布、模型初始化、计算预算与评测合同。
CPU正确性、真实模型采样、GPU训练效果分别报告。

## 当前版本边界

本次仅增加计划和导航，未改游戏、题库、solver、标签、prompt、D或训练默认值。
生产active仍为`terminal-node-regret-grpo-readable-v8`；V9仍是未激活草案，
已有评分缺口意味着不能仅凭历史CPU检查宣称完整新协议训练就绪。
所有后续语义变更另建版本并记录完整差异和实际运行快照，不覆盖旧实验。
