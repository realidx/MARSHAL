# H2稀疏S原因诊断v1

用户于2026-10-24要求检查S稀疏的原因。父版本为关闭的`three-player-local-audit-v1`。
游戏、reference、Q/S定义、prompt、D和训练均不改变，active保持v8。

1. 对全部31个已测父游戏的原标签作只读分类：无可遗漏信息、所有单条遗漏均唯一可恢复、
   有歧义但S为零、有正S；同时分解阶段、Q是否全平、私有答案遗漏组和数值门槛。
2. 预定深度诊断样本：每目标数首个private-S正游戏；首个3目标零S及前两个4目标零S游戏；
   加原35已知公开信号对照。不得根据新诊断结果增补成功案例或更换正式父池。
3. 固定原reference，逐world对当前玩家做完整后续max/min备份；宽度为零时证明其own utility
   在该world下不再受自身后续动作影响。这个宽度是诊断界，不替换Q。
4. 联合遗漏仅作为冗余诊断：移除入口已有的所有历史，或入口已有历史与调查答案；
   保留基础事实、承诺、待回应offer、额度、合法动作、自己的偏好，并保留入口后所有新观察。
   这些复合值不是主S标签，不激活成组遗漏协议。未来新观察必须通过cutoff0等价性检查。
5. 用独立sequence LP检查复合诊断见证，以及有歧义但原S为零的私有遗漏组。
   LP使用既有60秒限制/1e-9可行性容差，放宽回应次级社会约束；不声称跨均衡结论。

每次实际执行独立保存完整pipeline_snapshot。全批标签审计后冻结样本，再运行完整父游戏probe。
probe单worker、构树180秒、每case诊断软预算300秒（组间与控制界循环检查，非外部硬限）；
未完成者保留缺失，不计0。CPU验证不代表GPU或模型效果。
