# 游戏与标签设计 v2：下一次自身行动窗口检查

2026-10-22。独立研究实现`next-own-proposal-commitment-window-v1`。
父设计为[v1](../game_design_v1_20261021/DESIGN.md)。用户同意检查有限规划窗口；
本版仅检查可执行语义、规模、求解与行动价值，不切换生产active或生成正式训练题库。

## 相对v1的改变

| 项目 | v1 | 本次检查 |
|---|---|---|
| 求解目标 | 从当前节点至原生terminal | 从入口至当前玩家下一次proposal完成，包含报价回应；不足时到terminal |
| Proposal入口 | 完整剩余游戏 | 标准轮转下两人3次、三人4次proposal机会 |
| Response入口 | 完整剩余游戏 | 当前回应后，完成回应者下一次proposal及其回应即截止；不额外补满1 RR |
| 边界评分 | 原生终局utility | 截止时已生效承诺按原生binary/linear规则计分；无延续策略或价值网络 |
| Q | 全局定义尚待正式落实 | 检查窗口内、固定所选其他玩家profile时，自身完整contingent best response的入口Q；仅诊断 |
| S | 终局信息遗漏的设计语义 | 后续拟相对于同一窗口评分定义；本次不实现或测量新S，不把事前调查收益当S |
| D | 最终prompt下模型实测，未测 | 仍未测；Q/S/D联合选题未激活 |

整棵窗口树共享入口决定的一个绝对截止点。窗口内不逐节点刷新截止点；
所有玩家按同一边界utility与自身信息求解。不能称为滚动规划均衡或原游戏终局均衡。
窗口边界可能低估窗口外的延迟收益，故这里只检查候选评价器，不宣称已经证明其教学合理性。

## 保持不变

原100父游戏及其hash、人数/目标/隐藏偏好/两轮配置、独立均匀先验、原生合法动作、
提出即扣一次OFFER额度、调查耗回合且不允许查公开/本人已查偏好、信息披露与response平局规则。
不改prompt、模型、GRPO、reward/advantage、训练或历史reference。
不导入85份终局profile作为新窗口标签；只复用原生环境、信息集、求解和认证代码。

## 预定检查

- 100题全部做精确公共历史计数；此处的物理状态缓存只加速计数，不合并求解信息集。
- 求解名单在运行前固定：原六个规模分层各前2题，与远端未认证15题取并集，共26题。
  这是覆盖与失败诊断子集，不能用其通过率估计整池通过率；失败不补题。
- 本地CPU：2 worker、每worker数值库1线程；构树20秒、求解20秒、独立审核30秒。
- max nodes=100000、sweeps=128、candidates=6、joint cells=16384、joint evaluations=320、
  large-tree ordered sweeps=2；uniform起点；自身偏离容差1e-8、响应平局容差1e-9。
- 接受时仍检查窗口完整行动树、私有信息约束、单边偏离、局部支持及response社会平局；
  未通过者无标签。不会为取得通过结果放宽容差。
- 五项语义CPU测试覆盖人数对应跨度、response入口、提前终局、末次报价完整回应与计分、
  调查答案持续可见且对他人私有。测试中延长到3 RR的结构仅为边界夹具，不替代原100题。

实际CLI、完整参数、source副本/hash、环境和结果另存运行目录`pipeline_snapshot.json`。
结果登记时区分计数、已求解/认证、未测S/D、未训练；不覆盖v1或旧实验。
