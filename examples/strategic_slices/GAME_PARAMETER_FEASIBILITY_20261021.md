# 2026-10-21：生成先验、规模与行动额度的首轮可行性检查

状态：CPU诊断完成，尚未冻结新正式100题，未改生产游戏或prompt，未测新S/D或训练。
用户授权先联合检查参数与生成方式，再确定随机生成100个游戏的方案。
本报告不把“求解容易”当作正式题库的研究覆盖标准。

## 1. 本轮实际检查了什么

完整协议见[PROTOCOL](../../new/game_design_feasibility_20261021/PROTOCOL.md)。
独立实现[design.py](../../new/game_design_feasibility_20261021/design.py)支持整数调查/报价额度，
报价提出前扣额度且不返还；调查消耗提案机会、答案仅本人可见且持久保留。
没有覆盖生产代码、旧题库或已关闭版本。

生成隐藏偏好使用公开的独立均匀先验want/neutral/avoid各1/3，保留全部支持。
隐藏位置不依赖偏好取值。不强行把抽到的偏好改为want。
旧`catalogues.validate_catalogues`要求每个类型至少有一个want，且不允许任何目标
可能全员neutral。本轮独立诊断明确移除了这两项题库准入限制；native状态/计分允许这种情况。
这是实验条件变化，不是生产bug修复，也不意味着正式题库已经决定取消这些限制。

参数包括：2/3玩家，每人1—2种承诺，2—4目标，2/3轮，调查1/2次，报价1/2次，
隐藏偏好单元1—4个。不是所有维度全笛卡尔组合；每次实际配置完整保存在运行快照。
每个目标涉及至少两位玩家、最多三个承诺，允许一位玩家贡献两个承诺。

另明确区分两个不同游戏的调查菜单：

- `all`：保留旧规则，允许调查他人的公开偏好或自己查过的偏好。
- `hidden-unobserved`：只允许调查尚未直接查过的非公开偏好。

第二种菜单会改变公共信号和策略集合，不能称为保持均衡不变的剪枝。
尚未启用为正式规则。两种菜单下均不自动隐藏或删除合法的PASS、报价或回应。

这些是114次配置/种子的诊断尝试，包含配对菜单、额度条件和重复游戏的不同资源预算，
不是114个独立父游戏，更不是已经生成并认证的新正式100题。

v1：最多30000公共历史、900000 node-world pairs；20秒求解、30秒审核/辅助指标。
50组配置，每组固定两个seed。v2：隐藏单元降到1/2，最多180000历史、1700000 pairs；
60秒求解、45秒审核/指标，128 sweeps、16384 joint cells、320 joint evaluations。
v3沿用v2资源设置，以新固定seed检查每人2种承诺、3/4目标的更丰富双人结构。
每个运行两个CPU进程，数值库每进程1线程；v1与v2有重叠运行，v3在它们结束后运行，
耗时不作为单独硬件吞吐基准。

跳过与超时均不产生标签，不记成零信息或零难度，不替换seed，不用旧profile补新标签。
v3的两个三目标案例中，一个超时、一个候选未通过完整偏离/平局审核；
四目标的两个案例均通过。因此“目标少一定更好求解”并不成立。

完整终局求解均禁止非终局截断，并独立核对真实枚举节点数和预先计数。
所有接受的profile经过完整单边偏离、局部自身最优支持及回应平局规则审核；
不宣称唯一均衡、全局收敛或形式上的sequential equilibrium。

没有把不同历史合并求值，以免消除行为传递的偏好信息。

## 4. 暂时能支持的设计判断

1. 固定、公开的独立先验是可执行的基线；均匀并非已被证明最优，不能把诊断结果归因于先验。
2. 应把隐藏单元数、每人的承诺数和调查菜单纳入规模控制，不仅看人数/轮数。
3. 两轮、调查1、报价1是值得优先扩展的组合：允许先调查后报价，也让错误试探消耗额外报价资源。
   不因此要求每个玩家都调查；三轮和更多调查额度在旧全树方法下明显更昂贵。
4. 2—4目标可以继续研究，不能仅按本轮极少seed挑选“最容易”的目标数。
5. 三人多轮的可靠标签仍是实质瓶颈。原菜单下没有新求解成功证据；
   受限菜单的成功不能用于宣称原游戏已解决。人数比例尚未冻结。
6. 原先“每人必须有want”等准入条件也需要作为明确设计讨论，不能默默按求解成功保留或删掉。

这里只测初始提案者的完整终局行动价值和调查机制辅助指标。
禁止以后调查的收益差不是新定义的逐条遗漏S；没有测语言模型D。
部分认证初态有严格调查优势，部分没有；无法由两个seed、单一入口或Q跨度
判断正式题库质量，更不能据此声称模型训练有效。

## 5. 当前待决：调查已公开或本人查过的偏好

用户正在考虑是否保留此类行动，尚未批准修改生产规则。
建议在新协议中从合法目标里排除：调查提供的信息确定、不会重复确认或改变偏好，
无需将这种接口冗余作为核心推理难度；tools应直接排除，不给出后再施加隐蔽的非法惩罚。
只按明确的公开事实和本人直接调查记录排除；不根据solver推断或真实隐藏world决定菜单。

此建议不声称这些行动在所有均衡中被PASS弱支配：它们的目标选择、额度消耗和公开可见性
也可能用作信号，排除它们会改变游戏。该变化应由新规则、solver和后续prompt共同体现。

无需为了惩罚浪费额外增加回合/调查成本。现有机会成本若降低终局收益，Q会反映；
若不降低终局收益，按现有效用目标平局合理。改成“少用调查也更优”是另一项目标变更。
