\label{sec:experiment}

We evaluate whether training improves partner inference, action selection, and
their composition in \textsc{BENAC-I}, and whether any gains transfer to other
multi-agent tasks. We report the checkpoint and evaluation protocol with every
result; update counts alone do not imply equal training-token budgets.

\subsection{Data and training}
\label{sec:experiment-training}

We construct training items from slices of the finite \textsc{BENAC-I} game in
Section~\ref{sec:benac-i}. Instances vary goal dependencies, binary versus
linear satisfaction, private preferences, commitment states, and interaction
histories. We use the certified reference policy of
Section~\ref{sec:game-slices} to obtain behavioral likelihoods for
partner-state judgments and action values for legal decisions. We retain a
supervised item only when its reference computation succeeds, and check
generated transitions with the native game rules. Complete-game resets provide
a separate source of interactive experience. The final dataset
version, counts of distinct source structures and rendered training items, and
the exact structural separation from each test suite are to be inserted here.
% TODO: Insert the final dataset manifest, train/validation counts, and split audit.

All arms initialize from Qwen3-4B-Instruct-2507. The \emph{baseline} is the
unchanged model. \emph{SP} trains on complete self-play games using each
player's own terminal utility. \emph{O} trains on history-to-action decision
items, scored against the reference action values without a supplied partner
judgment. \emph{D} jointly trains O, partner inference, and planning given a
correct qualitative partner judgment. In the planning task, the model sees the
current decision state but not the behavioral history; the supplied judgment
uses the same possible-set/favored interface as the inference task. These are
alternative training objectives, not separate networks or an enforced
inference-to-planning pipeline at inference time.

We use grouped policy optimization with eight responses per decision item;
SP groups complete-game rollouts by reset and player. Training uses BF16,
a 4096-token sequence limit, at most 1024 generated tokens per call, sampling
temperature 1, and a KL penalty toward the frozen base model. The intended
response-token budget is 6,553,600 per arm, with actual consumed tokens and
checkpoint selection reported alongside each result. D collects four
candidate groups from each of the history-to-action, inference, and planning
tasks per update. Other optimization
settings, including each arm's learning-rate schedule and realized training
dose, will be taken from the archived run configurations.

\subsection{Transfer to CalBench and ShapeFactory}
\label{sec:experiment-transfer}

CalBench~\citep{zou2026calbench} asks privately informed agents to coordinate
calendar meetings while managing individual scheduling costs. Our sequential
transfer suite runs four homogeneous agents through three meetings in each of
24 frozen games. We measure full-stream completion and the number of meetings
jointly scheduled; cost is interpreted only for successfully completed games.
This small-model adaptation is distinct from the original benchmark aggregate
score and from our fixed-partner \textsc{BENAC-I} test.

ShapeFactory in CollabSim~\citep{chen2026collabsim} tests coordination through
production, trade, and fulfillment of private orders. Our native three-agent
setting uses three product specializations and one non-specialty order per
agent. The same checkpoint controls all seats across two supply-cycle
directions and private versus shared-dashboard visibility, for four games per
model. We report fulfilled agent orders out of 12, games in which all three
agents fulfill their orders, and final balance. The current v3 protocol retains
these four ShapeFactory conditions; verified v3 model results are pending.
