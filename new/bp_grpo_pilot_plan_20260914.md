# B/P GRPO 首轮参数提案

2026-09-14。状态：用户已接受并已实现首轮方案；冻结题库与脚本见 `examples/social_bp/README.md`，实现核验记录见 `new/bp_grpo_pilot_ready_20260914.md`。尚未启动远程 GPU 训练。以下保留参数讨论依据；实际差异：结构隔离与能力覆盖需要 42 个训练家族（不是初估的 24–32）；基础设施异常直接停止，本版不自动 retry。所有配额和阈值均为首轮实验选择，不宣称已验证最优。

## 开训条件

不用等全部复杂 social reasoning 场景准备完毕，但当前 51 道开发题和旧 B-only launcher 不能直接作为新的 B/P 联合训练。

需要完成：

1. 将无目录题面、B 原生提交与 P 原生行动工具接入同一训练导出、parser、reward worker，保留任务区分和独立评分。B、P 同一模型混合训练，P 始终直接给 belief。
2. 补齐首轮短题的能力桥梁和反事实对照，生成下述训练/验证/测试划分；标签含糊题排除，隐私/合法性/终局收益检查通过。长程标签明确针对选定伙伴策略，不假定策略唯一。
3. 接入二元任务奖励及新的分层 sampler，核对实际抽样比例、按题分组的优势、梯度积累后的真实 batch 和 Adam 更新次数。

开训前只做少量端到端原生调用与更新检查，不再为追求 base model 全部答对反复修改 prompt。小样本未采到正确不能直接删题；但整层只有全错组，应补桥梁而非声称 GRPO 会自动产生正例。

## 数据规模与定义

| 划分 | B | P | 总题数 |
|---|---:|---:|---:|
| train | 128 | 128 | 256 |
| validation | 32 | 32 | 64 |
| test | 32 | 32 | 64 |

一道题 = 一个具体合法状态/历史/已知信息下的 decision checkpoint。重命名、复制和单纯换 likely 同义词不增加独立题数。数据规模为目标，不能靠近重复填满。

先少量机制模板、约 24–32 个训练游戏家族，构造不同合法偏好、真实历史、时机和承诺组合的配对实例。验证和测试使用各自独立游戏家族；同一根游戏的相邻 checkpoint、因果对照和名字变体放在同一 split。机制模板可以共用，但不能把同题改名字当未见游戏。现有 probe 已用于设计，不作为最终未见测试集。

128 道 B：formation 48、maintain 32、update 48。抽样比例 3:2:3，按多步窗口实现。直接给所问偏好真值的任务最多 24 道，实际 B 抽样占比不超过 20%。全集与缩集、maintain 与 update、单元素与多元素 favored 都有配对；按家族采样，禁止由语句/名字变体数决定权重。

128 道 P 分成四个主要任务池，各 32 道：

- 完美信息短决策：正确计算完整报价的收益，含自身收益和利他平局。
- 给定不完整 belief 的短决策：比较具体报价；含可稳健评分的定性支持和少量联合约束。
- 使用已给信息：私有调查结果、给定更新 belief 后，选择实际后续行动。无需 P 自行完成 B。
- 信息获取决策：调查正例 16、匹配的不调查反例 16；负例包含仍有后续机会但无需调查，不只“调查就结束”。正例至少包含简单自身收益价值和利他价值，均须实际 solver 验证，不按设计意图强贴标签。

这些是主要任务标签，信息条件/利他/时机等可作为交叉属性。不要仅按动作名判能力已覆盖；不同 OFFER 必须在具体承诺与后续收益上有对照。第一轮不强求四人长局和所有 favored 反转方向齐全，但不能缺单步行为更新和实际影响选择的信息正例。

每个 B/P 池按难度总量各准备 easy 64、medium 48、hard 16。难度以推理依赖和 learner 后续决策次数定义，不以正文长度定义；基线与训练采样用于校准，不以两次失败断言能力不可学。

## 训练规模与超参

| 参数 | 首轮值 |
|---|---|
| 初始模型 | 本轮 probe 相同的 Qwen3-4B-Instruct-2507 初始权重；不沿用失败训练 checkpoint |
| 训练方式 | 同一模型全参数 GRPO；保留现有 BF16/DeepSpeed 路径，不新增 LoRA/SFT 阶段 |
| 最大 rollout/update 轮次 | 100 |
| 每轮不同问题 | 16：8 B + 8 P |
| 每个问题独立回答 | 8，始终使用同一个 prompt，原生工具格式 |
| 每轮生成回答 | 128 |
| PPO epochs | 1 |
| 目标有效 optimizer batch | 128 回答，按实际数据并行数配置梯度积累；目标每个 rollout 轮次一次 Adam 更新 |
| 学习率 | 1e-6，前 5 次更新 warmup，之后恒定 |
| PPO clip | 0.2 |
| KL loss coefficient | 0.01，冻结初始模型为 reference |
| entropy bonus | 0；记录 entropy，不同时新增调节方法 |
| task reward | 正确且合法提交 1；模型答错、截断、格式失败 0；基础设施失败不入更新 |
| response max tokens | 1024 |
| prompt max tokens | 4096；导出按真实模板 token 数检查，超长直接报错，不静默截断 |
| temperature / top_p / top_k | 0.8 / 1.0 / disabled |
| repetition penalty | 1.0 |
| length penalty | 0 |
| 作答 retry | 0 |
| 基础设施 retry | 最多 1 次，相同 payload，保留尝试日志及去重 |
| seed | 20260914；首轮一个训练种子 |

100 轮对应 1600 次题目抽取、12800 条训练回答，若均匀抽取则每题平均被抽 6.25 次、生成 50 条回答；课程采样下各题次数不同。这是学习趋势 pilot，不是最终收敛保证。回答上限约 1311 万生成 tokens，不含验证、提示输入、训练前后向计算。

这里的 step 明确定义为新 rollout 加一次完整更新。当前 ROLL pipeline 的 global_step 是外层循环；必须确保 effective batch/梯度积累配置匹配，不能只改 max_steps 而让每轮暗中多次 Adam 更新。GPU 数和 microbatch 根据 SoC 实际分配设置，不在未知资源情况下给墙钟耗时承诺。

## 难度曲线

B/P 始终 1:1，在各自能力内应用同一目标曲线；下表替代上一份审查中通用的 60/20/20 初始建议，使本轮计划可直接实现。

| 轮次 | easy | medium | hard |
|---|---:|---:|---:|
| 1–20 | 70% | 25% | 5% |
| 21–60 | 40% | 50% | 10% |
| 61–100 | 20% | 50% | 30% |

easy B 包含单步行为排除、无信息维持，不等于只读真值。easy P 包含两种完整报价、自身收益、利他平局、最后机会不要调查。medium 加报价行为比较、多元素 favored、给定信息后行动、最短两次 learner 决策的信息获取。hard 才逐步加多个未知偏好、联合约束、3 人轮转、累计证据；不扩大成很长的完整对局树。

以上为目标日程，而非不顾表现强制进阶。B 与 P 分别检查：连续两次验证，当前主练层的行为/决策题首答正确率达到约 60%，且匹配反例没有持续退步，才增加下一层比例；否则保持上一阶段比例，仍保留下一层探索份额。阈值只是操作起点，小验证集的单次波动不用于硬判学习失败。

按 10 轮窗口实现配额，在配额内部优先抽成对题。全集正确/错误、调查有用/无用等必须在同一难度中都有曝光。不同题的回答不能组成一个 GRPO group。全正确和全错组保留记录，不通过“重试直到成功”补齐有梯度组；不启用按正确率无限重采的 dynamic sampling。

DAPO 的动态采样处理了零优势组带来的效率问题（https://arxiv.org/html/2503.14476v1#S3.SS2），但本轮首先固定能力覆盖并观测哪些层没有正例，不直接套用会改变有效训练分布的过滤。二元任务 reward 下，名义 B/P 1:1 不保证有效梯度也 1:1，需要独立统计。

## 验证、保存与观察点

- Step 0、10、20、…、100：固定 64 题，每题 4 次独立作答，共 256 条；temperature=0.8、max_tokens=1024，与训练同接口，无 worked examples、无 retry。
- 验证一共最多 2816 条回答。最终选定 checkpoint 后 test 64 题、每题 8 次，共 512 条；不反复查 test 选模型。
- 每 10 轮保存；保留最近两个可恢复训练状态和一个最佳模型权重，控制磁盘使用。最佳模型按 B 各技能、P 各任务池分别宏平均后 B/P 等权选择；同时检查行为 B/因果对照退步，不以直接真值题拉高的总分替代能力改善。
- 10/20 轮检查错误奖励、提交和截断；30 轮是首次训练趋势诊断点，不默认宣称 30 轮足以收敛，也不自动扩到上千轮。
- 连续两次验证的关键能力明显下降时冻结难度升级并定位；某能力层训练持续全错时保持探索并补桥梁，不靠加大长度惩罚或重复简单读取题解决。基础设施、评分或梯度异常则停止该次训练并修复。
- 原始输出、工具参数、标签、长度、每题 group 成功数、分层抽样数、实际更新次数和 checkpoint 哈希均保存。每次验证报告错误全集率、误缩集率、favored-only、调查正反例、完整报价正确率、成对同时成功率和分层截断率。

首轮目的是证实：有奖励的社会行为区分逐渐增加，且能在未见游戏家族的匹配对照上同步改善。是否延长步数、增大题库或改变 B/P 比例由这一轮决定，不在 base model probe 上直接推断最终训练能力。
