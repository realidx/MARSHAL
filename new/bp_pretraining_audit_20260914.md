# B/P 训练前审查：题面、标签、课程与训练信号

日期：2026-09-14。结论：当前短题的主要错误有明确可核验的正确解，不能据 base model 答错就修改题面或强制推理格式。但当前开发题包还不是可直接开训的课程，奖励中的格式差异也可能强化错误答案。第一轮训练建议采用单次作答、二元任务奖励，不另加长度惩罚。

本次只增加本审查记录与本地可复现审查脚本。未修改冻结题目、模型输出、旧评分、线上服务、训练奖励实现或运行中的任务。以下训练设置是本次决定的下一版规格，尚未接入训练器。

## 1. 审查范围与核验强度

- 冻结运行：`new/local_data/social_runs/bp_soc_download/846561.952bhmc2/`，64 条正式 base-model 回答，32 个条件，每个条件两次独立采样；不是 GRPO 更新结果。
- 当前完整开发包：`new/local_data/social_runs/bp_readable_prompt_review_v2/tasks.jsonl`，75 个呈现条件，按 native_task_id 去重为 51 道题（24 B、27 P）。其中仍包含同一游戏的措辞变体，51 不代表 51 个独立游戏家族。
- 脚本：`training/b_sft/debug/audit_readable_pretraining.py`。机器可读结果：冻结运行目录下 `pretraining_audit.json`。

复现：

```sh
/private/tmp/social_native_tools_venv/bin/python -m training.b_sft.debug.audit_readable_pretraining --out new/local_data/social_runs/bp_soc_download/846561.952bhmc2/pretraining_audit.json
```

核验结果：

1. 32 个冻结请求的 system、实际问题正文、工具 schema 与当前 renderer 一致。没有内部动作数组、隐藏目录、策略哈希、行动价值泄露。带教学条件的例题是明确标记的教学演示，不能当成独立泛化测试。
2. 从玩家可见的公共偏好与公开生成规则重新枚举所有合法未知偏好组合，未以隐藏的人工候选目录限定支持集。16 个求解根节点重建后，51 道题的当前状态、pending offer 与保存标签一致；18 个已给旧 belief 也重新核验一致。
3. 25 道题额外通过独立逆向计算：直接用 ALL_OF 和终局收益计算动作，按自身、他人、残余均匀平局选择，不读取 teacher 的策略或缓存价值。只有各真实信息集内策略一致时才接受这项核验；这避免偷偷让玩家看到完整世界。
4. 27 道 P 中，26 道当前已经是最后提案机会，另行用终局收益与响应者的信息核验每个动作的条件价值，均一致。唯一的长程调查根节点仍是选定策略下的条件性标签，不能把重跑同一 solver 当成证明所有合理策略都给出相同答案。
5. likely 标签重新通过原有区间 LP 审查；这是对记录的宽语义区间成立，不是证明英文词汇有普遍数值定义。两道 `possible` 题仍无共同稳健动作，不得加入硬奖励训练；已评分的 SoC 子集未包含它们。

这些结果支持当前短题标签有依据，不等于证明 solver 对任意复杂游戏都可靠，也不证明模型一定能学会。

## 2. 错误样本的题面与标签依据

| 题目/错误现象 | 题面已经提供的关键信息 | 可核验的标签依据 | 判断 |
|---|---|---|---|
| one_response_accept：把成交后的承诺当成报价前已有，输出全集 | starting offer 与自愿 ACCEPT 分开；报价不绑定；ACCEPT 后新绑定内容明确 | 最后响应时，want 接受获自身收益；neutral 接受帮助 Alex；avoid 拒绝。故保留 want/neutral，等支持 | 当前证据是时序推理错误，无需补“答案提示” |
| one_response_reject：围绕 Harbor 反复论证 | Orchard/Harbor 各自要求双方的哪些承诺明确 | 同一报价被拒绝，仅 avoid 相容；想实现 Harbor 不会让 neutral 拒绝一个帮助 Alex 且无自身损失的最后报价 | 可训练的候选比较错误 |
| one_offer_forms_singleton：只看 Blair 的 Cedar，忽略报价另一半 | 明列 proposer 与 partner 的新增承诺，说明需要 ALL_OF | Blair 对 Orchard 为 want 时，两种完整目标报价自身均得 1；neutral/avoid 时分别得 0/−1，而 Harbor 报价得 1，不能选择观测到的 Orchard 报价 | 标签有行为排除依据，不能用“未披露”保留全集 |
| maintain_favored_goal_0：重置旧 belief、重新引入 avoid | 正确旧集合 want/neutral、favored=want；旧/新历史标记；新事件为 Alex 接受 | Alex 在两种剩余世界均接受，新证据似然相同，因此集合与 favored 都保持 | 可训练的维持错误；无需禁止正常自检 |
| joint_unknown_favored_disappears：忽略联合约束 | 每个玩家至少 want 一个 goal，两个未知偏好均保留 | 五个合法联合世界中，观察 Harbor 报价提升 Orchard neutral/avoid 相对支持，二者并列；集合不变，favored 从 want 变 undetermined | 有真实“集合不变而倾向更新”对照 |
| private_result_want / acquisition_avoid：把一个承诺当作整个目标完成 | 双方承诺清楚；偏好是真实私有答案；已知事实未广播 | 用两个玩家的完整新增承诺逐目标计算，能区分正确报价、错配报价、PASS | 可训练的目标组合与利他平局推理错误 |
| acquisition_same_game_last_turn：调查后还打算下一次报价 | 只剩当前机会；之后 learner 机会为 0；调查消耗当前机会 | 调查立即终止且不新增承诺；正确报价有正的自身期望收益 | 是合理而简单的“不调查”反例 |
| qualitative_*：likely/certain 后仍调查 | 已给当前 belief；只有最后一次提案机会 | 调查价值为 0，而正确报价获正自身收益。是否该调查无需先精确解释 likely 数值 | 不能据此把错误统称为“likely 机制有问题” |

本次没有找到必须靠重写上述题面才能解答的实质遗漏。阅读负担仍可能影响 base 表现，但不能据此强制模型遵循某段人工 reasoning。可用更小的合法题构建课程，不给待答题填入候选排除结果。

## 3. 对照存在，但课程还不完整

B 的 24 道题：formation 6、maintain 7、update 11；标签集合 1 元素 12、2 元素 6、3 元素 6。恒答“全集 + undetermined”只能通过 6/24。**因此不是完全没有反例。** 但 8 道直接给出了所问偏好的调查真值，占 11 道 update 的 8 道；真正的行为更新、favored 出现/反转、连续形成再更新仍薄。所有 B 均标为 stage 0，不能认为已形成难度阶梯。

`one_offer_changes_favored_only` 这个旧 source 名尤其不能用于计数：扩展无目录支持后，其正确旧、新标签完全相同，实际 skill 已是 maintain。现有有效 favored-only 更新例是 `joint_unknown_favored_disappears`，且只有这个更新方向；不能用名字或同题重命名填满覆盖表。

P 的 27 道题：24 道接受动作属于 OFFER，1 道为 INVESTIGATE，2 道信息含糊不计硬标签。其中 14 道来自同一 qualitative 游戏的词汇/措辞变化。此处统计的是**动作类型**，不意味着任意 OFFER 能得 24/25 分；具体承诺组合仍须正确。但调查正例几乎只有一个机制，且主要体现利他收益，没有形成足够简单的“信息改善调查者自身收益”阶梯。最后回合的负例已经不少；还应补有后续回合但无需调查、目标选错、调查一个偏好后仍需处理剩余不确定性等合法对照。不能强行捏一个“不调查必错”的规则。

当前题包全部是 development_probe、training_ready=false。现有 `social_b_grpo.py` 和 `examples/social_b/grpo.yaml` 使用旧 B 课程与旧 renderer/export 路径；不能将本次 probe 的覆盖直接视作实际训练分布已修复。

下一版课程按能力分别搭阶梯，而非先学完全部“简单 B”才第一次接触行为题：

| 能力 | 起步 | 中间桥梁 | 后续 |
|---|---|---|---|
| B 形成 | 单个自愿接受/拒绝，只有一个相关目标变化；另配无信息响应 | 两种合法报价比较；同自身收益时的利他层；非单元素 favored | 多未知偏好的联合约束、跨行动证据 |
| B 维持 | 正确旧 belief + 一个不区分候选的新响应 | 旧 favored 明确但不更新；新动作看似相关却不区分 | 自行形成后连续维持 |
| B 更新 | 私有真值只作入门；同时提供简单行为排除题 | 正确旧 belief + 单步缩集；只改变 favored | favored 出现/消失/反转，累计历史 |
| P | 完美信息下两种完整报价的收益比较，单独加入利他平局 | 不完整 belief；使用已给调查结果；调查根节点与最后机会匹配对照 | 两次 learner 决策、较大局面、调查后仍不完全知道 |

每一层都有保持/改变、调查/不调查、不同完整报价的反事实对照，而不只是逐步增加字数。先保留少量可反复练习的游戏家族，不追求大量新游戏。家族及其重命名、措辞、教学版本不得跨 train/validation 泄露。

起步采样规格：按能力与因果对照家族分层，不按文件行均匀采样；直接读真值的 B 暂设不超过 B 抽样的 20%，其余优先短行为与对应无信息控制。每个能力池按当前难度 60%、较易复习 20%、下一层探索 20% 起步，缺失的能力阶梯先补题，不用重复易题填充。这些是待用训练实测调整的初始配额，不是经过验证的最佳比例。

全正确 GRPO 组通常没有任务奖励优势，不会因为“都得 1”而持续产生同方向任务梯度；问题在于有效梯度集中在哪些能力，以及错误回答是否相对获奖。全错组也不应因此永久删除：保持探索份额，检查是否需要合法的中间难度题，不能无限重采直到撞中答案。

## 4. 本次明确发现的奖励风险

旧奖励为正确 1、合法错误 0、截断/格式失败 −1。32 个双采样组中：

- 8 组全正确；19 组无正确；5 组有正确与失败对照。
- 19 个无正确组中，4 个分别出现 0 与 −1；按组中心化/标准化后，错误答案会获得正优势。
- 这 4 个条件是 B 接受题原名、B 接受题重命名、P 利他平局、P 私有 want 结果。两个 B 的 0 分回答都是错误全集。
- 总共 9 个奖励有差异的组中，4 个差异来自“答错但完成”对“截断”，而不是正确社会推理。

这不是声称本次 probe 已强化错误（本次没有训练），而是可直接算出的训练信号风险。哪怕把 −1 改成一个很小负数，只要全错组内仍有差异，组标准化仍可能放大它。

**下一版 B/P optimizer 决定采用二元完成任务奖励：**

| 结果 | 训练任务奖励 |
|---|---:|
| 原生工具调用合法，且 B 集合/favored 完全正确或 P 属于可接受集合 | 1 |
| 合法但答案错误 | 0 |
| 截断、缺调用、非法参数等模型输出失败 | 0 |
| 基础设施失败、标签无依据/语义含糊的题 | 不进入该次更新 |

这不把截断前的 reasoning 判为错误逻辑，只表示此次未成功完成提交。不额外奖励工具格式；正确提交自然包含格式要求。保留各失败类型指标。二元奖励下全错组不产生任务优势，意味着必须靠有可学习对照的课程获得正样本，不能指望换奖励自动创造能力。

旧结果与旧奖励字段保持不变；新规格应独立版本化并在新训练导出中接入，不能悄悄重写历史评分。基础设施丢样时不把剩余组缩成较小组来更新；补齐独立有效请求或跳过整组并记录。

## 5. Retry 与 length penalty 的决定

### Retry

第一轮不加模型作答 retry：不因答错、截断或没有 tool call 就追加“再想想/现在提交”。本批 40 条未截断回答已有 39 条合法原生调用，主要瓶颈是 reasoning 未完成，并非普遍的原生接口失效。重试成功不能替代第一次失败，更不能拿 teacher 的正确与否决定偷偷重采。

仅允许基础设施重试：一次请求未得到可用响应时，以完全相同 payload 最多重发 1 次，记录 request_id、attempt_id、原因；重复返回去重，只保留一个完成响应。已有 length/stop 的模型响应不是网络失败。第二次仍失败，跳过该训练组并记录，不填 0 分假样本。

如未来单独研究自我修正：独立实验，最多一次中性反馈、不含 gold；第一答与第二答分开记录，首答正确率和修正率分开报告，不把带反馈的第二答混入原问题 GRPO 组。SCoRe 的自我修正也是显式多轮训练目标，不能把其结论等同于“给现有单轮 GRPO 加 retry 就更好”：https://arxiv.org/abs/2409.12917 。本轮不接入。

### Length penalty

第一轮 `length_penalty_coef=0`，维持当前 1024 输出上限，不增加 repetition penalty、不设置“超过若干句必须提交”的推理模板。二元任务奖励已让没完成答案得不到成功奖励。全局长度扣分会让同组全错时的短错误相对获奖，可能鼓励迅速提交全集，恰好偏离目标。

DAPO 专门指出截断惩罚可把有效长推理当作负信号，并研究截断 loss masking 与软超长惩罚；这说明处理方式必须区分，而不是越短越好：https://arxiv.org/html/2503.14476v1#S3.SS4 。该结果不证明我们的 1024 上限足够；本批循环错误也不证明所有长回答都无价值。

如果后续模型已能稳定作对，但正确回答仍存在明显冗长，再做独立消融：仅对**正确且本组同时有正确/失败样本**的回答施加小额超阈值扣分；错误样本一律仍为 0，全正确/全错误组不开长度项。可试初值：768 tokens 以下无扣分，768–1024 线性扣最多 0.05。正确答案奖励仍至少 0.95；不额外对截断扣负分。阈值与系数是实验初值，非当前已经启用的参数。不能通过整组长度差异归一化单独制造全错组的优势。

## 6. 训练验收与当前剩余工作

训练前还需要：将当前无目录、原生行动工具版本接入正式 B/P 导出；完成上述桥梁题和成对家族；为长程调查正例保留选定策略条件并补简单自身收益信息价值案例；过滤无稳健标签的题；接入新奖励版本及分层采样。

验证在 step 0 和每 10 步进行，既有 B 配置已设 eval_steps=10，无需声称这次才改。固定验证集不 retry，不因训练采样重加权而变更构成。至少报告：

- B 按 formation/maintain/update、真假全集、集合大小、favored-only 变化分层；重点单看行为题，不能被直接读真值的正确率淹没。
- P 按调查有用/无用、正确目标/错误目标、调查后使用答案、具体报价、利他平局分层；同时统计匹配对照两边都正确率。
- 首答正确率、合法提交率、截断率；正确/错误回答分别的长度分布。
- 每能力池的全正确/有成功对照/全错组比例与实际采样数；不要把格式导致的 reward diversity 当成能力学习信号。

每题两次 base 采样不足以证明某能力完全采不到成功，或确定最佳难度顺序。保留 base 错误供训练改善；当前应修的是课程桥梁和训练信号，而不是逐条把模型的 reasoning 改成我们想看的样子。
