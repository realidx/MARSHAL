# 一、首先要承认：当前 P 已经不是原先的“给 O 加正确 belief”

这次最重要的设计变化是：

- O 保留原生历史，并使用原二元行动评分。
- P 删除历史、prior、私人调查结果和证据来源，只保留当前状态及定性 belief。
- P 使用正／负／masked 三态监督，实际 reward 已不再与 O 完全相同。:chatgpt-content-reference{index="1"}

**我不建议为了恢复原来的叙述，再把历史或数值 posterior 塞回 P。** 当前方案可以成立，但需要准确命名它检验的处理条件。

## C−O 现在检验的是一个 P 辅助训练包

它包含：

> **从原生历史决策中抽离推断负担，提供定性伙伴判断，并只对可稳健判定的行动进行监督。**

因此，C 优于 O 时，可以说这个 P 辅助训练包有价值；不能单独说收益“只来自提供正确 belief”。历史长度、输入任务形式和部分监督规则也一起改变了。

这不是实验失效，而是**比较对象应与实际实现一致**。

## D−C 仍然是有解释力的消融，不必因此增加第五个训练臂

当前：

\[
L_C=\frac23L_O+\frac13L_P,
\]

\[
L_D=\frac13L_O+\frac13L_B+\frac13L_P.
\]

D−C 回答：

> **保留相同 P 候选曝光和总预算时，将部分 O 监督替换为 B 监督，是否改善无辅助表现？**

这个问题是有效的。不要把“不能识别固定 O 剂量下的净增加效果”扩大成“完全无法识别 B 的作用”。

但是，下面两个问题确实不同：

\[
\text{用 B 替代部分 O 是否值得？}
\]

\[
\text{O、P 剂量均不变时，额外增加 B 是否有效？}
\]

你们现在做前者。**在时间紧张的情况下，我建议坚持前者，不追加训练臂。** C/D 已固定每块三个相同 P 候选组，这是很有价值的控制；实际 P 的可评分比例或梯度不同，则可能是两种训练路线产生的结果，不应为了强行匹配而继续补采样。:chatgpt-content-reference{index="2"}

# 二、P 的 LP 认证：最关键的不是再增加数字，而是确认“认证条件没有藏在被删除的历史里”

你们已经做了两项正确的工作：

**一是检查定性表示不足以确定评分的反例；二是匹配关系只有在逐世界完整 payoff 表一致时，才作为改变 belief 的对照。** 这比只检查“物理状态相同”严谨得多。:chatgpt-content-reference{index="3"} :chatgpt-content-reference{index="4"}

但当前还需要补一项必要检查。

## 1. LP 的世界集合，必须与 P 实际可见的条件相容

设 P 实际看到的请求是 \(z\)，允许的 belief 集合是 \(\mathcal B(z)\)。认证的意思应当是：

> 对所有与 \(z\) 相容、且在声明范围内的 belief，某个动作都应判正，或者都应判负。

**风险在于：当前 LP 可能只在原始历史已经筛选后的 teacher 世界集合内改变权重。** 如果某些世界是因为历史证据才被排除，而这段历史现在没有给 P，那么这个集合可能比 P 输入所允许的集合更窄。

例如，仅作说明：

```text
两个未知偏好的边缘判断都为：
possible = {want, neutral}
favored = undetermined
```

它没有单独告诉 P，两者是正相关还是负相关。如果后台世界集合因为原始历史只保留了某一种相关关系，那么在该集合内通过 LP，不等于这些可见定性判断本身足以支持同一行动。

文档已经诚实地将认证限制在“现有 teacher 世界集合与固定后续策略价值表”。**这个限制应保留，同时增加世界集合中每类约束的来源标记：来自当前可见状态、公开规则、定性 belief，还是来自已经删除的历史。**:chatgpt-content-reference{index="5"}

这里不必立即重建所有求解器。但不能把“没有发现重复 P 输入对应不同标签”当作充分证明——那只能说明当前有限样本中没有直接冲突。

## 2. 三态标签应有明确的正、负认证义务

建议把以下条件写成评分器合同。设 \(R_{\mathrm{orig}}(a,b)\) 是原评分规则：

\[
a\text{ 被标为正}
\ \Longrightarrow\
\forall b\in\mathcal B(z),\ R_{\mathrm{orig}}(a,b)=1,
\]

\[
a\text{ 被标为负}
\ \Longrightarrow\
\forall b\in\mathcal B(z),\ R_{\mathrm{orig}}(a,b)=0.
\]

其他动作可以 masked。**不要求你必须把所有可认证动作都找出来，但已经标正、标负的动作必须满足对应条件。**

另外要确认三件事：

**源 posterior 属于允许集合，且允许集合非空。** 否则“对所有允许 belief 都成立”可能成为空集合上的无意义通过。

**认证的是实际原评分规则，不只是精确自身 argmax。** 你们保存了自身精确最优集合与原 acceptable 集合，并明确原评分包含容差及 response tie 约定；两者不能在 LP 中混用。:chatgpt-content-reference{index="6"}

**浮点边界不确定时，保守进入 masked／待审查，而不是用容差将其悄悄判成正或负。** 这尤其适用于严格支持集合和 favored 阈值附近。

## 3. 支持先用直接终局题验收，但不要把它变成新的主训练范围

你们报告有 174 个“所有直接后继均为终局”的案例，在两种定性范围下都稳健。:chatgpt-content-reference{index="7"}

**我支持先从其中属于 train 的案例里，选有明确正负动作的少量题，做原生转移、标签和一次 GPU 更新验收。**

它们能减少“固定后续策略到底承担了什么”的复杂性。

但这只是工程锚点。直接终局题可能根本不需要多少伙伴推断，不能只在这类题上成功，就宣布完整 P 辅助训练已经可行。之后的短程校准仍应使用正式计划中的多步、信息获取和结果利用案例。

# 三、保留 O/B、屏蔽不合格 P 是正确的，但现在最容易缺的是“真正被采到的正负对照”

你们当前实际 P 训练池是 **314 题**，不是 420，也不是 453；其余角色的处理已经区分清楚。保留有效 O/B、仅隔离不合格 P，我支持，不建议再统一删掉整个 parent。:chatgpt-content-reference{index="8"}

不过，三态评分引入了一个必须在 Q0 上量化的新问题。

## 1. 存在正负动作，不等于八个回答里会同时出现正负动作

设模型对某道 P 题：

- 输出可判正动作的概率为 \(p_+\)；
- 输出可判负动作的概率为 \(p_-\)；
- 其余为 masked 或无效回答。

八次独立采样中，同时出现正、负回答的概率是：

\[
q
=
1-(1-p_+)^8-(1-p_-)^8
+(1-p_+-p_-)^8.
\]

这是由采样规则直接得到的计算，不是对当前 Q0 的实测估计。

例如：

\[
p_+=p_-=0.05
\]

时，可评分回答中的正确率是 50%，看起来并不极端；但一组产生语义对照的概率只有：

\[
q\approx10.36\%.
\]

每块三个 P 候选组，平均仅约 **0.31 组**有正负对照。

因此：

> **三态屏蔽可以避免错误监督，却也可能让 P 的名义 \(1/3\) 权重实际上很少产生任务梯度。**

这不是要求给 masked 动作负奖励，也不是要求恢复无限补采样。你们当前只在合法且可评分回答中中心化，确实避免了“正确＋非法”冒充语义对照，应保留。:chatgpt-content-reference{index="9"}

## 2. Q0 探测至少输出这一张表

按 O/B/P，以及 P 的终局／非终局、未知偏好数量和来源分项，记录：

| 必须记录 | 作用 |
|---|---|
| 正、负、masked、非法、截断的数量 | 不让条件正确率隐藏大量不可判分输出 |
| 候选组数、语义 mixed 组数 | 确认实际任务信号 |
| 不同 case／parent 的有效组覆盖 | 避免少数题贡献全部更新 |
| 输出长度、加权任务系数 | 检查固定 1024 分母下的实际力度 |
| 全对、全错、仅一个可评分回答的组数 | 区分饱和、无正反馈与屏蔽导致的零信号 |

**不要把 P 的条件正确率上升、覆盖率下降，直接解释为规划改善。** 也不要把 masked 当成错误或遗忘。你们当前文档的处理原则是对的，缺的是实际模型数据。:chatgpt-content-reference{index="10"}

## 3. 100 块的确定性日程，应先做一次完整覆盖审计

按照当前计划：

\[
100\text{ 块}\times3\text{ 个 B 组}=300\text{ 次 B 题组选取}.
\]

但训练 B 有 373 题。所以即使完全不重复，**这轮预算也无法让全部 B 题至少出现一次**。P 同理，300 个候选组槽位少于 314 个 P 训练案例。实际还会因相关案例重复而进一步减少唯一案例覆盖。:chatgpt-content-reference{index="11"} :chatgpt-content-reference{index="12"}

这不意味着方案不合理；只是：

> **保留全部数据、拥有完整覆盖序列，不等于在本轮预算内完成全部覆盖。**

建议先不改比例，直接离线展开全部 B/P 辅助槽位，输出：

```text
实际出现的 case / parent / source family 数量；
零曝光的来源；
无合格 P 的 B 来源是否仍出现；
相关题与控制题的重复次数；
调查前与结果利用分支是否均得到曝光。
```

**优先保证来源家族和关键推理结构被访问，而不是坚持每一行都必须访问。** 如需微调，只调整固定序列中的未覆盖 parent 优先级，不根据模型 reward 动态追采。

这比继续扩充题库更有优先级。

# 四、主 checkpoint 指标：我建议改成固定 Q0 伙伴，而不是继续扩大 current-team

这是我认为进入正式训练前最重要的一项评测修改。

当前主选择规则是所有玩家都使用当前 checkpoint。文档已经明确它不是固定 Q0 伙伴。:chatgpt-content-reference{index="13"}

**这个指标有效，但它衡量的是同质团队表现。** 如果将所有玩家的自身 utility 求平均：

\[
\frac1n\sum_i U_i,
\]

它数值上就是平均社会福利，而不是“某个被测玩家面对固定伙伴的收益”。即使只取某个座位，其他玩家也随 checkpoint 改变，仍然存在伙伴变化。

这会造成一个实际问题：

> 你可能用 current-team 选择出最适合同类伙伴的模型，却把论文主结果解释成对固定外部伙伴的策略能力改善。

## 我的最小建议：替换伙伴设置，不先增加实例数量

沿用已经冻结的完整交互 dev 初始局，把设置改为：

```text
[M, Q0, Q0]
```

只更新 M，伙伴 Q0 的 checkpoint、提示、推理设置和环境协议固定。开发阶段可以在既有调用预算内平衡 focal 座位，不必立即将每个实例扩成三倍。

主选择仍可使用：

> **固定伙伴下的全样本 focal utility 保守下界 → O parent-macro → 更早 checkpoint。**

current-team 指标保留为次要监测，特别适合与你们的 CalBench 同质团队结果相互参照。**不是把它删除，而是不让它代替单体交互的主选择目标。**

## 25 个静态案例可以先保留，但优先利用已有的六个 must-change 对

你们目前静态面板有 25 个 canonical cases，实际发送 73 个视图；两个 B→行动对照仅涉及三个局面。与此同时，validation 中已有六个 payoff 表一致的 must-change 对。:chatgpt-content-reference{index="14"} :chatgpt-content-reference{index="15"} :chatgpt-content-reference{index="16"}

**先检查这六对能否全部成为清楚的对照，不需要立即生成更多题。**

每一对要分别确认：改变的证据是否影响实际被查询的 B，两个 P 请求是否除定性 belief 外保持相同，以及当前三态正动作集合是否真的不相交。

不能满足“只改变所查询 B”的关系，可以保留为一般历史敏感性测试，但不要硬算成单变量 B 干预。

同时报告 must-change 与 must-stay 的配对成功。这样才能避免把“模型变得更容易改变动作”误判成“模型更会根据证据调整动作”。

# 五、我建议的短程校准流程

**不要在所有条件都尚未验证时，直接将四臂各跑满 6.55M；也不必先研究出一种新的防遗忘算法。**

下面是我建议的有限流程。

## 阶段 A：无训练的输入与可训练性验收

先完成真实 tokenizer 下的实际请求渲染，包括 system prompt、工具描述和 chat template；不只量正文长度。确认 O/B/P 各自没有静默截断、没有不应出现的历史字段，且与证书版本对应。

随后，从 train 中预先分层选一小组 canonical cases，覆盖直接终局、多步、不同未知偏好数量、相关题和控制题，使用训练采样设置，每视图八次，获取上面的信号表。

**这里的通过标准不是 Q0 分数高，而是：任务定义清楚，模型有机会生成可判定的正负对照，关键来源不是全部靠非法回答制造差异。**

若某类八次全错，这只是风险信号，不是成功概率为零的证明；但没有必要在尚无正反馈证据时就期待长跑自动解决。原始 GRPO/Dr. GRPO 研究也将能否探索到正确回答作为训练可行性的重要检查。:chatgpt-content-reference{index="17"}

## 阶段 B：最小 GPU 工程验收

利用直接终局小批，检查：

**实际聚合 loss 与参考公式一致；microbatch 切分不改变累计结果；恢复前后同批计算一致；一次更新前后的模型版本、概率和参数变化能对上。**

现有更新前概率阈值是合理的工程报警，但不能把平均误差和至多八条抽查当成全批认证。至少应按 O/B/P 分项，记录已计算 token 的误差分位数、ratio／clip 情况，并补一次更新后的变化检查。附件已经明确当前门禁不覆盖全部 batch 和更新后的过大变化。:chatgpt-content-reference{index="18"} :chatgpt-content-reference{index="19"}

HF 两个 norm 张量上的梯度 cosine 可以保留为局部观察，**不需要把它扩大成完整可解释性项目**；但至少一次要在实际 Megatron 训练路径上核对分项 loss 与梯度聚合。局部 cosine 为负，只能说明该组参数上的即时方向冲突，不能直接诊断整个模型的长期遗忘。

## 阶段 C：有限的归一化与辅助校准

建议固定为：

| 校准运行 | 预算 | 目的 |
|---|---:|---|
| O，`centered_fixed` | 8 块 | 检查默认归一化 |
| O，`standard_sequence` | 8 块 | 检查另一已实现归一化 |
| C，选定的共同归一化 | 8 块 | 检查 P 辅助接入后的表现 |
| D，同一归一化 | 8 块 | 检查 B 替代部分 O 后的表现 |

每次从同一 Q0 开始，使用预定输入日程。共约 **2.10M 训练响应 tokens**，另计探测和评估成本。它是固定的小型校准，不是不断搜索到 D 获胜为止。

**最容易漏掉的一点：八块短跑必须使用正式 100 块的 cosine horizon。** 也就是运行正式计划的前 8%，而不是把整个 cosine 压缩到八块，在结尾已经降到 \(10^{-7}\)。否则短程验收不再对应正式训练初期。

两个归一化选项同时改变标准差与长度归一化，这一点文档已说明清楚。Dr. GRPO 的论证支持检查这些权重效应，但不保证在你们的部分监督和小任务库中默认方案一定更好。:chatgpt-content-reference{index="20"} :chatgpt-content-reference{index="21"}

如果八块不足以区分两者，**保留预先指定的默认值，不继续延长到一定出现赢家。**

# 六、遗忘／漂移：现在应加密监测，不应急着加一种“防遗忘机制”

你们已明确当前做的是可观测性和部分风险控制，而非已经验证的能力保持方案，这个定位正确。:chatgpt-content-reference{index="22"}

## 1. 短程不能只评估 25%、50%、75%、100%

- **短程固定伙伴完整交互：** 0、4、8 块。
- **正式训练保持监测：** 静态面板每 5 块；正式候选 checkpoint 仍只取 25%、50%、75%、100%。

这样能看到早期漂移，又不会通过增加可选 checkpoint 数量给某个训练臂更多“挑最高点”的机会。有限开发集上的反复模型选择本身会造成选择偏差，所以密集监测与可选模型集合应分开。:chatgpt-content-reference{index="23"}

## 2. 不必现在实现性能自动回滚，但要明确报警条件

我的建议是：

**工程硬失败立即停止在 optimizer 前或停止后续更新。** 包括概率门禁、非有限值、数据身份冲突、恢复不一致。

**能力退化先报警，不立即自动调 LR、KL 或回滚。** 一个可预先固定的工程规则是：

> O parent-macro 相对之前监测点下降至少 0.08，且至少两个 parent 出现相同的“此前正确→当前合法错误”，连续两个监测点存在，并经同协议复测确认，则暂停短程校准进行检查。

0.08 是建议的工程阈值，不是统计显著性或灾难性遗忘定义。重要的是同时要求**跨 parent、持续、合法语义回归、可复现**，而不是一个题变错就触发。

正式比较时，不应因为 D 出现退化就回滚继续挑好点，却让 O/SP 保留末端结果。任何停止或选择规则都必须共同适用，预算末端、所选模型和中断原因分别报告。

## 3. 根据观察决定查什么，而不是立刻追加约束

| 短程现象 | 首先检查 |
|---|---|
| O 自己也不学习或明显退化 | 概率链路、loss 聚合、归一化尺度和 O 可训练性 |
| O 正常，C 退化 | P 的可评分覆盖、辅助输入／reward 合同、P 与 O 的实际梯度关系 |
| C 正常，D 退化 | B 的行动相关性、B 信号覆盖、O 被替代的实际剂量 |
| B/P 变好，O 不动 | 辅助技能是否回到无辅助决策，不把教学题成绩当成功 |
| 静态 O 改善，固定伙伴完整局不改善 | 短窗口到完整互动的连接、grounding 和伙伴行为分布差异 |
| 只有 current-team 变好 | 先按团队协调改善解释，不直接归因于单体伙伴建模 |

这些是排查路径，不是每行已经对应一个被证明的因果机制。

# 七、我会要求的最小修改清单

**数据与标签层：** 保留 373 个 train O/B 和当前 P 角色筛选，不统一删题；补 LP 世界约束来源与正／负认证合同；先用直接终局题做工程锚点，不将主训练缩成终局题。

**曝光层：** 离线展开 100 块辅助日程，报告零曝光来源；Q0 探测实际的正／负／masked 分布和语义有效组，不用“314 道合格题”替代可训练性证据。

**实验解释层：** C−O 定义为定性、去历史、部分监督的 P 辅助训练包；D−C 定义为固定预算下 B 替代部分 O。暂不增加剂量匹配训练臂。

**评估层：** 主开发交互改成固定 Q0 伙伴；current-team 保留为次要指标；优先审查已有六个 must-change 对，而不是马上扩大题库。

**校准层：** 先 Q0 与 GPU 门禁，再执行有限短跑；保留完整 token horizon，加密静态监测，但不自动增加正式 checkpoint 选择机会。

**总体而言，这版最值得肯定的是：你们已经不再用更复杂的 B 标签掩盖 P 输入不足，也不再把 masked／非法输出混成普通错误。接下来不需要再次推翻方案。**

但进入长跑前，必须回答两个非常具体的问题：

> **P 的正负标签是否只依赖它被允许使用的条件？**  
> **在真实 Q0 分布下，这些标签是否经常形成能进入更新的语义对照？**

**这两项通过，再加上固定伙伴的共同开发选择规则，就足以支持一次可解释的短程校准。它仍不保证四臂出现预期排序，但能让“不提升”也对应一个清楚、可定位的问题，而不是再次陷入数据、辅助信息、损失尺度和评测对象全部混在一起的情况。**
