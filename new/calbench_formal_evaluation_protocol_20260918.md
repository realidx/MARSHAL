# CalBench 正式评估结构设计

状态：设计稿 v1；尚未生成、验证或冻结正式实例，尚未运行正式模型。2026-09-18。

## 1. 研究问题与实验单位

问题：BENAC 训练后，模型组成的同质团队能否在不同机制的私有日历协商中，更可靠地完成会议，并降低整个团队的实际调整成本？

主实验各自使用四个相同 checkpoint 的独立 agent：Q0×4、SP-only×4、Mixed×4。BP-only checkpoint 可用时加入 BP-only×4，作为监督任务训练的对照。四名 agent 分别维护私有观察和历史，不共享上下文。这里 Mixed 是训练方法名称，不是已删除的 mixed 目标类型。

固定 12 个初始场景，每种模型跑一次，相同场景逐一配对：主实验 36 局，加入 BP-only 后 48 局。不存在 focal player，因此不追加三次或四次座位轮换。12 个场景中的参与者身份、先发言身份及时间位置预先平衡；这种置换不计作新结构或额外样本。

这是一项小规模、定向的跨环境迁移评估，不是官方 CalBench 全榜复现，也不用于声称适应广泛异质对手。

## 2. 统一环境范围

- 4 名玩家、8 个时间槽、每个会议持续 1 槽；每个实例新增 1 个三人会议。
- 初始状态可以包含 0、1 或 2 个已有三人会议。已有会议是环境事实，不声称由被测模型在此前谈判中自主形成。
- 保留原生日历、blocked 事项、可移动事项、私信、VOLUNTARY、决策校验及失败处理。所有隐藏日历仅供生成器和评分器使用。
- 私人事项调整成本取原始单位 1、3、8；旧会议每位参与者调整成本为 1，团队迁移成本必须计入外部参与者。使用自定义固定成本分布，不套用官方 leaderboard 的归一化分数。
- 每个实例独立重置。原生环境在一次失败协商后可能保留局部合法写入；本设计不再接下一场新会议，因此不会把这一状态差异扩散到后续测试。

代价：本实验测已有承诺下的协调，不能支撑长序列会议流或自主建立承诺后的长期规划结论。

## 3. 十二个结构模板

以下是生成约束，不是已经验证的具体日历。所有实例都必须可解；不把失败任务的零调整成本当作优解。每组内部改变可行时间交集、成本承担分布或会议依赖关系，不能仅替换名字、槽位或随机种子。

| ID | 结构与生成约束 | 主要检查 |
|---|---|---|
| F1 | 恰有一个三方共同空闲槽；每一对玩家还各有一个不被第三人接受的共同空闲槽 | 能否整合三方可用性，排除两两可行的假共识 |
| F2 | 恰有两个共同空闲槽；其他槽有私人阻塞；固定顺序下各人的首个私人空闲槽不一致 | 多个同优答案下能否形成一致选择；不要求唯一答案 |
| F3 | 三方空闲集合呈严格包含关系，最受限玩家仅有一个空闲槽；其余人拥有额外选择 | 是否响应最受限参与者的信息 |
| F4 | 一个零成本共同空闲槽，另有两个可通过移动私人事项达成的槽；无旧会议 | 是否避免不必要的调整；不能把移动事项当成通用成功策略 |
| D1 | 两个可行槽，分别由一个人承担成本 8、另两人各承担成本 3；无共同空闲 | 少数人的集中高成本与多数人的分散低成本，选择团队成本 6 |
| D2 | 两个可行槽，分别由一个人承担成本 3、另两人各承担成本 3；无共同空闲 | 与 D1 配对控制：不能固定保护唯一承担者，团队最优为 3 |
| D3 | 三个可行槽，各由不同玩家承担单项调整，成本依次为 1、3、8；无共同空闲 | 三方私人成本比较；没有固定的两槽选择模式 |
| D4 | 两个可行槽，成本向量分别为 (1,3,0) 与 (3,0,1)，其余槽不可行 | 多个成本相同但分配不同的最优方案，协调到任意一个均正确 |
| C1 | 一个旧会议与新会议重叠两人；新会议唯一可行槽占用旧会议；旧会议有两个全员可行迁移槽，其中一个还需移动外部者的私人事项 | 必须联系外部者，并在多个迁移目的地中选择较低成本方案 |
| C2 | 一个旧会议与新会议重叠两人；新会议有两个可行槽：移动旧会议总成本 3，或保留旧会议并调整一项成本 8 的私人事项 | 两条可行路径中，主动协调外部者改约有价值 |
| C3 | 与 C2 相同的依赖类型，但保留旧会议的私人调整成本为 1 | 成对控制：应保留旧会议，不能见旧会议就改约 |
| C4 | 两个不同的旧会议分别占用新会议的两个候选槽；两个旧会议均与新会议重叠两人；迁移其中一个只需全员会议迁移成本 3，迁移另一个还需额外私人调整 | 在两条承诺依赖路径之间选择，不必同时移动两场旧会议 |

补充约束：

1. 私人事项必须有合法的迁移目标；不能只计算“清空候选槽”的费用而忽略移入位置。生成器必须检查最终日历可行性。
2. C1/C4 的额外私人调整必须在原生单批次动作规则下可执行；若需要原生不支持的连锁清空顺序，就重构实例，不扩展规则。
3. 旧会议均为三人会议，在四人环境中与新三人会议至少重叠两人。不得设计实际上不可能出现的“一人重叠”。
4. D1/D2、C2/C3 是有意保留的结构匹配对，只有决策相关成本改变；它们不是四个独立拓扑证据。正式报告同时记录 12 个场景、3 个大类和这些共享结构关系。
5. F1–F4 不全是困难题。它们提供基础协调和避免无效改动的控制条件，不能只保留 Q0 难题。
6. 两个已运行开发场景不进入正式集。不承诺所有正式依赖模式都与开发集不同；允许复用机制，禁止把这种复用称为结构 OOD。

## 4. 模型与调用预算

沿用已经跑通的开发调用设置，避免看正式结果后调整预算：4 轮交流、1 次决策重试、每次最多 768 输出 token、32,768 上下文、temperature=0。精确定义以冻结的原生 config 和 adapter 参数为准；保存每局实际调用次数。

保持原生提示和隐私规则；不增加策略提示、正确时间槽、成本排序、完整日历或 JSON 约束解码。关闭算法 fallback 和隐私 reflection。保留原生解析与修复流程，记录每次尝试，不能仅统计修复后的成功调用。

固定 checkpoint 路径及内容标识、tokenizer、推理版本、dtype、原生源码文件哈希、adapter 版本、提示、种子和生成参数。temperature=0 也不宣称跨硬件绝对确定。

两张 A100-40G 各加载同一个待测 checkpoint 的一个副本，同时运行两局；一局内四名玩家共用该模型服务但保持独立历史。按模型批次切换 checkpoint，无需同时容纳多个训练变种。队列和场景—副本映射对所有模型相同。API 接口保留，正式本地运行禁止隐式外部回退。

## 5. 正确参考与验证门槛

参考动作、完整日历和最优成本仅进入 evaluator，不进入玩家 prompt。参考是全信息可行性/成本基准，不是同可见信息的可部署 oracle player。

F/D 组可用原生静态 solver 交叉检查，但必须回放原生动作验证迁移位置及最终一致性。C 组不能使用原生静态 solver 作为精确 oracle：已确认它会漏计旧会议外部参与者的调整成本。

每个实例在冻结前必须具备：

- 完整原生 scenario、来源、模板 ID、共享结构组、可见信息规则；
- 明确的最优成本及证书：穷举这个小实例的相关最终安排并检查合法动作可达性，或者给出覆盖所有候选路径的下界证明及达到该下界的回放；
- 至少一个最优成功回放；存在非最优路径时再回放一个非最优成功方案；
- C 组再回放一个缺少必要外部协调的失败方案，确保原生一致性检查生效；
- 基于玩家—会议依赖及空闲/blocked/可移动状态的规范化结构签名，另存成本签名；检查与开发实例的完全重复及近似同构关系。

不能通过 solver 返回一个数就宣布验证完成，也不能在参考存疑时继续正式评分。验证失败只能依据预定约束修复，不运行候选模型筛选题目。

## 6. 指标与比较

本任务没有为“完成一个会议”定义与调整成本可直接相加的收益。因此不发明单一 social-welfare 标量；用完成率和团队调整成本共同操作化团队表现。

全体有效基础设施运行上报告：

1. **协调成功率**：新会议成功登记，所有参与者一致，全部旧会议仍一致，且没有不可移动事项违规。按 12 局及 F/D/C 各 4 局分别报告。
2. **成功且达到最优成本的比例**：分母仍是全部实例；失败计不满足。这是辅助联合指标，不替代完成率与原始成本。
3. **实际团队调整成本**：保存四人的成本及总和，包括失败局发生的真实调整。但零成本失败不能排在有成本成功前面。
4. **成本比较**：报告成功局成本及其样本数；模型之间额外报告双方均成功的配对实例上的成本差和超额成本。明确这是条件性比较，不用于遮蔽完成率变化。
5. **运行质量**：完整协议结束率、非法调用数/动作提交次数、原生拒绝批次数、截断数/生成次数、基础设施失败数。协议正常结束与会议成功分开。

不使用 cost ratio（最优成本可能为 0）、原生含不完整 oracle 的复合分数或关闭测量后的 privacy 默认值作为主指标。

每个模型对报告逐实例成功/失败配对表、双方成功时的成本差；同时展示原始 12 行结果。每组只有四个实例，且包含匹配结构，不据此给出强显著性结论。不把 token、调用次数或局内玩家当作独立样本。若以后扩大测试，按结构组抽样并增加实例，再确定区间估计；当前不报告把 12 局视为独立同分布的精确置信区间。

## 7. 失败、冻结与结果边界

网络连接、服务崩溃或显存故障属于基础设施失败；保留原始尝试，修复后允许相同配置最多重跑一次。再次失败则该实例在相关模型比较中标记缺失，单独报告，不填零收益。若修复改变了推理或环境语义，升级协议版本，不能仅对失败模型使用新设置。

模型输出非法动作、不能达成一致、用完轮数、输出截断均保留为模型/协议结果，不为了得到成功而重跑。所有提交过的尝试写入 attempt manifest；禁止只保留最后成功的日志。

冻结顺序：生成 12 个实例 → 无模型的规则与参考验证 → 核对结构/成本签名及开发集重合 → 保存 manifest 与 SHA256 → 固定模型清单和执行预算 → 正式运行。正式模型只接收原生可见信息。冻结后不按任何模型的成绩替换场景或增加交流轮数。

当前交付物是结构设计；实例、参考证书和正式 runner 接入是下一步实现工作。现有 `--suite structures` 仍然只运行两道开发题，不能当作正式套件启动。

## 8. 可以和不可以得出的结论

若 Mixed 同质团队在相同条件下完成更多会议，且成本表现也更好，可以支持“训练带来的能力在这组私有日历协商结构上改善团队协作”。若只提高成功率、成本没有改善，应如实分别表述。

该结果本身不能证明提升来自内部 belief 推断，不能排除 grounding/规则理解贡献，不能证明个体面对冻结对手更强，也不能证明真实生产 MAS、长期会议流或广泛未见结构的泛化。BENAC 的固定对手评估回答不同问题，应分别报告。
