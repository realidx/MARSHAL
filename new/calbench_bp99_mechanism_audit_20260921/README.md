# 新旧 BP99：CalBench 与 diagnose 的机制对照

2026-09-21。离线读取新同步原始结果；未调用模型、未修改训练、未改论文及 PRO_BRIEF。

主要判断：旧模型的优势集中在约束较强及后续交互的协调与执行；当前证据不能把它主要解释为显式 B 更准确，也不支持新版普遍更被动。更符合记录的候选解释是：新模型未稳定维护局部可行性、伙伴确认状态与实际动作后果之间的关系。该解释与 strengthened v6 的规划失败一致，但尚不能将退化因果归给 B bridge 或某个优化参数。

## 三个有定位价值的案例

### dense_uniform_s2：动作合法仍无法形成共同方案

- old三场全成，新版仅第一场成功；新版整局semantic-invalid为0、无截断。
- 第二轮old的agent 1、2分别向agent 3说明slot5已被旧会议占用，并建议slot6。agent 3最后也选6。old的agent1初次忘记移动errand，被拒后修复，最终全员6。
- 新版agent1把对方的“slot7有errand、建议slot5”误写成“agent3不能用slot5、slot7 blocked”，向agent2建议6，却未在这段记录中把纠正方案送达agent3。agent3继续建议5。
- 最终各自合法提交6、6、5，下一轮又是0、0、6。

来源：old `runs/calbench_soc/old-bp99-860494-biinv-v1-stream-868934/games/dense_uniform_s2/events.jsonl` 行60、63、75、79、83；new对应文件行51、54、59、68、70、72、76。

启示：不能只监督“自己的动作合法/局部效用正确”，还要监督伙伴反馈的保持、可移动与不可移动的区分、信息送达对象及共同承诺。旧模型在该例也错误声称slot6原本空闲；成功不是全程推理正确。

### replan_uniform_s3：局部确认交叉，最终意见分裂

新版第一轮：agent0提2，agent1说2 blocked、可用0或1；随后0改提1，1又提0，2分别收到不同更新并只发给一方。最后0相信已定1，1和2相信已定0，执行1/0/0。三人局部都声称已达成一致。old三轮全成，新版三轮均失败。

来源：new `.../replan_uniform_s3/events.jsonl` 行8、12、18、21、24、27、30、33、36、38、40、42、44、46、50。

在该case的初始agent0完整相同请求上，old询问伙伴在0/1/2中的可用集合，新版先提单一slot2；replan_uniform_s1也呈现此差别。这是可观察策略差异，不证明先报集合总是更好，也不能把早期提2直接归因为最终失败。全24局仅找到24个完整相同请求对；自然轨迹很快分叉，不能把后续case相同当成输入相同。

启示：需要区分提议、局部接受、已传达的修订、共同确认；“我能做”与“大家会做同一件事”不同。不能直接把自然语言说明当作可信状态标签。

### blocked_varied_s2：已找到共同空位，却执行相反的状态变换

old第一轮全员直接schedule到3并成功。new也同意3，但agent1、2分别将slot2的errand移入slot3，再把会议安排到3；其解释是这样可以“腾出”slot3。批次被拒，agent1重试仍相同，整轮失败。

来源：new `.../blocked_varied_s2/events.jsonl` 行41、43–45、48–52。第三轮agent0还尝试移动并不在自己日历上的item10（行136），涉及行动所有权混淆。

启示：这不是缺少更多伙伴belief，而是行动后状态计算错误。应增加无需移动、必须移出目标、不能移入目标及只能操作自身承诺的对照。

## 与 strengthened v6 的连接和边界

v6上两模型semantic B exact均5/32，voluntary exact和possible-set exact均0/16；新版possible-set改善来自preset。共同24例correct-B regret old .802、new 1.130。正确充分B下旧7次、新14次调查全部非最优。

diagnose的“明知最后一轮仍调查以便之后决策”与CalBench的“将errand搬入会议槽以腾空该槽”，共同表现为：语言上提到事实或目标，但最终动作并未正确实现它。CalBench另增加了多人消息传递、共同方案维护和连续状态的要求。

不能将CalBench失败全称为P：对伙伴消息、可行性和共同承诺的判断属于广义交互状态推断，超出当前v6单伙伴偏好B的覆盖。v6的B exact没有区分两模型，不排除CalBench相关的其他推断能力存在差别。

此前“过度调查/过度询问”仅可作为局部假设。新版发送DM更多，loose更好，现有案例里主动提案不少；数据不支持统一解释为更被动。也不能把通信数量直接当作沟通有效性。

## 对改进方案的约束

1. **数据优先补当前状态→行动后果及反馈→修订→一致执行的关联结构。** 在训练游戏中构造已有承诺、共享依赖、拒绝与修订、不能撤回的动作、不同剩余机会；不要把CalBench测试案例复制进训练。
2. **B保留语义真值，但不能以偏好exact覆盖全部交互推断。** 在可验证训练状态中分别标注可见事实、推断、伙伴已承诺/尚未同意、自己可控制的动作；不要凭解释文本判定模型内部信念。
3. **P的后台标签应包含执行可行性、状态变化、效用及机会成本。** 对最终动作评分的同时，可把确定性状态转移做少量辅助任务；不奖励看似合理但未经验证的长解释，不因为错误belief碰巧选对动作而反向标它正确。
4. **保持充足的无辅助历史→动作与短连续交互训练。** 单步teacher窗口可提升局部计算，但不足以自动教会修订和信息送达。辅助B/P+共享parent并检查撤掉辅助后的效果；少量连续训练仍用真实收益/可验证结果，不奖励发言或合作次数本身。
5. **优化和数据归因仍需分开。** 旧新同时改变采样、有效曝光、长度归一化、advantage与LR，现有轨迹无法辨认哪项导致参数变化。先量化实际任务梯度/曝光，再做受控短程比较。不能据本审计直接加大KL或认定B梯度有害。
6. **开发评测应分别报告同模型团队和固定伙伴单体。** 当前CalBench结果支持团队配置差异，不能替代固定伙伴迁移；新增对照应在独立开发实例上进行，不继续用这24局选择配方。

当前最有证据的工作假设是：旧BP较好地维持了受约束交互中从局部事实到可执行共同方案的能力；新训练未在本次v6中显示目标行为推断改善，且在CalBench复杂协调和执行环节更弱。其训练原因仍可能包括资源挤占、辅助任务不迁移、优化尺度变化或相互作用；不是已经识别的因果结论。
