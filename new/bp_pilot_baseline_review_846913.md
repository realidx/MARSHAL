# B/P 冻结题库 base model 基线审查：SoC 846913

结论：P 已有较多可用于短 GRPO pilot 的混合成功组；B 的形成和行为更新信号仍很稀，现有 easy/medium/hard 还不能视作已验证的平滑课程。没有发现这轮的主要失败来自题面传输、调查工具参数或明显错标签；也不能从八次全错断言某题不可训练。此次审查不修改题库、标签、prompt 或 reward。

## 数据完整性

使用完整运行 `runs/bp_pilot_probe_nus/846913.2babiyud/`：train 256×8=2048，validation 64×4=256，无基础设施失败，test 未运行。另一个目录 846900 在引擎初始化阶段退出，没有正式样本，未合并计分。

冻结请求、采样器、教师题库 SHA256 全部一致。320 条可见 request 与当前 renderer 逐字段相同；2304 条 API usage 的 prompt_tokens 全部等于启动时 tokenizer 计数，未发现题面被截断。全部 1126 条输出截断恰好发生在 completion_tokens=1024。输出预算不应因此直接扩大。

实际环境：Qwen3-4B-Instruct-2507，vLLM 0.28.0、Transformers 5.16.1、Torch 2.13.0，一张 H100 NVL MIG 3g.47gb、4 个 HTTP workers。这是基线 HTTP 采样环境，不能替代 ROLL 训练环境的端到端检验。

## B：全集 fallback 存在，但主导现象是循环后截断

Train 的非直接真值 B 中只有 140 条合法提交。77 条提交全集，其中：

- 60 条集合本身不该保留全集；
- 5 条集合可以是全集，但 favored 错误；
- 12 条完全正确。

行为更新的 61 条合法提交里，36 条直接保留了旧 possible set 和 favored，尽管这些题的正确标签确实应改变。它与维持题的较高成功相呼应，需要依靠维持/更新对照区分，不能只强化“复制旧答案”。

Train 的 favored-only 更新 16 次回答为 0 正确，validation 12 次也为 0。全部非直接 B hard 的 120 次回答为 0 正确。Easy 行为 B 18/480=3.75%，medium 15/352=4.26%；目前未显示预设难度梯度。

人工阅读的典型样本 `0699ae6fcd16e2a4db06`（两人、两目标，8 次全截断）：两目标都要求双方 Maple；Alex 对两个目标的收益相抵，Blair 已知想要 Harbor。Blair 却选择不能完成目标的 Cedar 报价。若 Blair 想要/中立于 Orchard，双方 Maple 会给 Blair 2/1 而该报价给 0；只有 avoid 时总收益相抵，该报价才可能与其他动作并列。标签 avoid 有简短可核验依据。

模型的文字却不断重复“不提 Maple 表示不喜欢 Orchard”，在 neutral/avoid/fullset 之间摆动，还把偏好解释成对某项 commitment 的直接喜好。另一些样本把尚待响应的 proposal 当成已遭拒绝。题面明确区分 pending、绑定和回应，因此这些例子没有提供必须改 prompt 的依据。

`4100103abffd240766bf` 的成功回答与截断回答也显示：同题可以采到正确提交，但正确答案旁边仍可能有不充分的理由，尤其没有真正用利他平局规则排除 neutral。不要把 correct=1 等同于整段 reasoning 已掌握目标逻辑，也不要据此擅自撤销合法正确答案的奖励。

## P：存在学习起点，调查高分需要用反例解释

Train 调查正例 103/128=80.5%，反例仅 15/128=11.7%。正例的 16 组中 11 混合、5 全对；反例 8 混合、8 全错。反例已有训练信号，不能因此判定 investigate 不可训练或机制应删除。

12 对具有相同目标、偏好和 supplied belief、只改变合法时机的调查正负例中，只有 4 对在正负两边都至少采到一次正确。五对正例 8/8，但相应负例 0/8；这符合默认调查在正例拿分、却没有学会时机区分的解释。它不能单独证明模型理解了信息价值。Validation 正例 6/16，负例 1/16；样本少，暂不据此单独断言泛化失败。

反例 `303bc60e1053656259a5` 题面明确只有当前一次提案机会，八次均选择调查，理由仍是“获取信息后再决定报价”。另一反例 `5792db873afc0dd2b4ca` 中，最优先加承诺的自身最终值为 2，调查则为 0；模型仍经常泛称信息有用，未计算少一次承诺机会的代价。

在后一个反例里还出现**动作正确但解释错误**：样本 0 选中可接受的 OFFER，却声称只加 Cedar 已满足要求 Cedar+Maple+Willow 的目标。这是合法正确首步，reward=1 应保留；但下一版应补“执行该首步后的决策点/目标仍未完成的对照”，使这一错误理解无法在相关题上持续拿分。

P 完整 belief 的错误也有明确模型能力成分：如 `954609a62dc6fe1e9c98` 把满足共同的一部分 prerequisite 当成同时完成两个目标，或在自身收益并列时未比较对方收益。题面的 ALL_OF、收益和剩余机会明确，暂无依据为了这些 base 错误继续加规则警告。

## likely 的成绩不能直接解释为语言机制失败

Train 16 道 qualitative 题的 128 次回答，正确 33；95 次错误中 90 次选择调查，3 次截断，只有 2 次是其他错误行动。这些题是末次提案：主要错误仍是把调查当作可用于后续计划，而不是直接暴露了 likely 的数值含义问题。

例 `adce505064badd9092b2` 已用文字复述“unlikely avoid”，随即决定调查后再报价。因此这轮无法充分隔离定性 belief 如何影响具体报价。后续可用合法的“调查额度已用”状态提供同类报价对照，再审查定性词和联合约束；不应先改成数字概率或把误解强行归咎于 likely。

## 题面、标签、接口与 reward 审查

- 选取九个有代表性的失败/混合组 checkpoint，再次从可见生成规则重建支持并求解；标签和选定策略哈希均匹配，原生合法性检查通过，定性题复核宽语义域内可接受行动集合。
- 本轮评分使用正确 1，其余模型失败 0；未发现错误全集因同组截断而获得正任务优势的旧问题。不得把基础设施失败算作普通 0，但此次完整运行不存在这类失败。
- 全部 train+validation 有 437 次合法 INVESTIGATE 提交，未观察到 investigate 专属格式失败。其大量语义错误不能解释为接口不稳定。
- 13 条格式失败：9 条 B 的 API 工具参数是缺少 judgments 外层的数组，4 条 P 一次 OFFER 提交两项自身承诺，违反每人最多一项。B 的数组问题只保存了 API 解析后数据，不能据此完全排除 parser 的参与；数量很小，不足以解释主要失败。训练启动的原生 token/parser 检查仍应保留。
- 旧统计里没有有效异答案对照的 cell 也会显示 contrast_accuracy=0。例如本轮 validation P/hard 没有该指标所需的组，不能把这一 0 解释为已测得全部对照失败；`analysis/statistics.json` 额外提供每层的实际对照组数量。

## 对下一步的判断

应修正此前“课程已可直接照计划推进”的表述：此前验证了题目合法、标签自洽和工程配额，没有验证学习难度平滑。这轮 base 实测提供了后者的证据。

建议保留当前题库作为已测基准，先细化 B 的最浅层行为形成/更新桥梁及其维持/更新对照，再做 20–30 步的短 GRPO 学习诊断，而不是直接把 100 步跑完。P 保留调查正负对照，优先补能检验正确首步背后是否有正确后续计划的 checkpoint。不要只增加直接披露题，也不要按此次全错删除困难题。

继续保持二元 reward、原生工具、无作答 retry、无额外长度惩罚、1024 输出预算；不能由这次推理错误直接推导出必须干预模型输出方式。短训练的观察重点是 B 行为形成/更新的混合组是否增多、错误全集/复制旧 belief 是否下降、P 调查反例是否改善，而不是总体平均 reward 是否上涨。
