# Tool-call 训练与 B/P 迁移：实验设计约束

2026-09-08。以下是待验证的设计建议，尚无 BENAC-P post-training 或 transfer 结果。

Tool call 是行动的输出接口。SFT 的梯度仍更新产生行动的模型，RL 也可以按终局
回报优化生成的行动；输出为结构化参数，不意味着只能学习 JSON 格式。
但 SFT 和 RL 都可能学会局部捷径，全参数更新也不能保证跨环境迁移。

## 相关证据与适用范围

- [ToolLLM](https://arxiv.org/abs/2307.16789) 的工具调用 instruction tuning 报告了
  未见 API 和 APIBench 的泛化。这说明工具格式不是迁移的必然障碍，
  不能据此推断它学到了 BENAC-P 的伙伴推断或承诺规划。
- [CodeGym，ICLR 2026](https://arxiv.org/abs/2509.17325v2) 在合成的可验证多轮
  工具环境上做 RL，报告了未见工作流/工具任务的改善。这支持研究训练分布与互动结构，
  但其环境、模型与 BENAC-P 不同，不是 Qwen3-4B 到 C2C 的效果保证。
- [PAFT，EMNLP 2025](https://aclanthology.org/2025.emnlp-main.37/) 在包含工具使用的
  SFT/RLFT 实验中研究 prompt 表述过拟合，并报告动态表述变化改善未见 prompt 表现。
  接口鲁棒性与跨机制迁移仍是两种不同的测量。
- [Small LLMs Do Not Learn a Generalizable Theory of Mind via Reinforcement Learning](https://arxiv.org/abs/2507.15788)
  报告其小模型 ToM RL 设置中域内提高而跨数据集收益缺失或下降。
  这是需要防范的实证失败例，不能扩大成所有小模型或所有 ToM RL 都不能迁移的定理。

## 容易学到的捷径

- 输出编号/标签的频率、动作列表位置、玩家名称、固定提示词。
- 固定 oracle 的 tie-breaking 和动作风格；对该伙伴获利不等于理解一般伙伴。
- 看到 proposal/ACCEPT 就机械判断 WANT，忽略多 goal 收益和行动者信息边界。
- 在有限残局里直接利用局部承诺模式，缺少前期保留选择和取证后使用信息的训练。
- 大量空历史 controls、所有行动同值样本，带来好看的 loss 而策略学习信号很弱。
- RL 的格式分、工具次数分或信息量代理压过终局目标；甚至合法 PASS 获得稳定奖励。

## 当前接口建议

保留语义 B 和原生参数化 P。P 使用已有 OFFER/MENU/PASS/响应 tools，提供参数含义
和环境规则，brief reasoning 可选。不要要求输出 Q、概率或人为 plan variable。
全动作列表加 action_index 保留为诊断对照，不建议作为大场景唯一训练接口。

训练变换分两类：改变玩家/goal/commitment 的表面名称必须同步变换规则、历史、
工具 schema 和目标行动；改变 tool/字段名称需提供准确说明并使用可逆 adapter。
不能打乱模型 tokenizer 的 tool-call 特殊标记或让 Hermes 与模板不一致。
所有派生版本与原游戏处于同一个数据划分，不能用改名伪造新游戏测试。

SFT 只对 assistant 目标输出计算监督损失；prompt 和环境/tool 返回不作为待模仿答案。
合法性是接口检查，B 标签来自证据支持，P 标签来自信息受限 teacher。
允许不生成 reasoning 的正确行动示范；若加入 reasoning，不能从全知 oracle
答案反向编造“当时已知道”的解释，free-form 文字也不是能力或因果机制的证明。

RL 的 outcome reward 使用实际执行轨迹的终局收益，单独报告非法调用和截断。
不能把回报设成“与某一个 oracle 动作字符串一致”，特别是有同值行动时。
若保留 SFT 辅助项或 B 可验证奖励，分别记录权重和消融；不能把可能集合缩小
直接等同于好推断。policy loss 应基于实际采样的 assistant token，环境反馈不计入。

## 区分迁移层次

| 检验 | 变化 | 可以支持的结论 |
|---|---|---|
| 同分布源游戏留出 | 新 seed/图，源家族隔离 | BENAC-P 内泛化 |
| 接口留出 | 未见名称、字段表述、动作排列，语义等价 | 对接口表面的鲁棒性 |
| 结构留出 | 人数、goal 依赖、horizon、组合结构 | BENAC-P 内结构泛化 |
| 伙伴留出 | 未训练的策略及随机性，先验范围明确 | 跨伙伴适应 |
| C2C 等环境 | 新规则、反馈与行动语义 | 跨环境任务表现迁移 |

至少分别报告 tool validity、B 语义正确性、P 决策价值/后悔值（可求解范围内）、
终局收益。B→P 修复与 P→B 干预仍用于可归因分析，不能只看总 reward。
纯格式熟悉的对照应使用与战略无关、可直接校验的接口练习；不要把错误策略
或随机行动伪装成“格式 SFT”的正确策略标签。其数据量和训练预算需匹配说明。

迁移评估同时保留 action-only 和显式 B→P 两种执行方式，避免 BENAC-P 专用
B 调用流程成为部署前提；两种方式的模型调用数与 token 预算单独匹配报告。
C2C 不能简单把“秘密目标”填成 BENAC-P goal 就算完成适配：环境的规则、状态、
行动和奖励需独立定义。可以共享消息/工具传输格式，adapter 不可代做伙伴推断和规划。

先冻结源游戏与结构划分，再生成变体。未见接口开发集可以用于调试，最终 C2C
测试集不用于筛模型或选 checkpoint；如使用 C2C 开发集，应另设未触碰的 transfer
环境或测试划分，并明确这已不是完全未接触目标环境的选择过程。

近期优先验证：参数化接口能否在保留原生动作集合的同时降低输入长度，并在不同
命名下保持正确行动；然后做小规模 B/P-SFT 的能力与接口分项比较。无需预设新 RL 算法。
