# Qwen3-1.7B 小规模 B/P 与 self-play 测试复核

结果目录：`new/local_data/social_runs/qwen17_probe/qwen17_probe_20260915-033340/`。
本轮只分析下载记录，没有启动训练，没有改变 prompt、标签、奖励或远程配置。

## 判断

基础设施执行成功：416 次正式 B/P 类回答、4 次预检和 48 条 self-play 尝试全部收集，退出码 0，无 HTTP 基础设施失败、OOM 或输出截断。但**当前 Qwen3-1.7B nonthinking 配置没有通过“可直接扩大 GRPO／混训”的可训练性检查**：

- 52 个 B/P 八次组中，仅 3 个同时含 0/1 奖励；42 个全零、7 个全一。49/52 个组在这次采样中的任务奖励 advantage 为零。
- 新 bridges 5/144 正确，仅一题产生全部 5 个正奖励；简化 L0 1/48 正确，37/48 输出全集。
- 416 个 B/P 回答没有一个自然语言解释。唯一非空 content 是未解析的工具标记，不是推理。
- self-play 31/48 局到达终局，17/48 局在一次重试仍无效后提前结束，终局 utility 为 null。12 个开局仅 6 个完成全部四次重复。
- 当前输出短、局提前结束，解释了墙钟显著缩短的一部分；不能用本轮耗时宣称引擎性能提高十几倍，也不能证明 1.7B 全参训练已经能在双卡完成。

这是少量事先选定条件下、固定模式的诊断结论，不是 1.7B 总体能力估计，也不能证明恒定组永远没有训练价值。

## 解释与模式

上传的 B/P system 仍明确写着 `Briefly explain your answer, then make one tool call.`；self-play response instructions 同样要求先简短解释。原始 HTTP raw_message 中也没有被独立存放的 reasoning_content。因此没有证据表明解释被客户端丢弃。

本次显式采用 `enable_thinking=false`，意图与原 4B Instruct 非 thinking 测试保持一致。但这种设置并未保证 1.7B 仍输出普通解释。**“关闭 thinking”与“保留普通解释”是两个不同的行为要求，后者实测没有稳定满足。** 不能把这次少输出、零截断当作推理表现改善，也不能只凭本次试验断言开启 thinking 就能改善。

Self-play 260 个首次决策中，仅 22 次有自然语言内容（8.46%）；全部 289 调用中，另有 9 次 content 只是缺 arguments 的工具标记。读到的自然语言解释仍出现身份／目标收益混淆、重复已有承诺等错误；没有把“存在文字”计作“推理正确”。

## Self-play 完整性与收益

全部 48 条尝试在本地使用冻结 runtime 重放通过；逐调用 raw 工具参数重新解码与记录一致。正常终局的 binary ALL_OF、linear 完成比例、utility、协议扣分和可见信息边界通过回放中的独立复算；失败轨迹的 terminal_reward、combined_reward 保持 null，没有偷填成 0。

| 指标 | 结果 |
| --- | ---: |
| 正常终局 | 31/48（64.58%） |
| 连续无效动作后中止 | 17/48 |
| 首次有效决策 | 231/260（88.85%） |
| 重试 | 29 次，12 次成功 |
| 无效调用 | 46/289 |
| 输出截断／网络失败 | 0 / 0 |

46 次无效调用的人工归因（包含首次和重试）：

| 错误 | 次数 |
| --- | ---: |
| INVESTIGATE 调查自己 | 20 |
| OFFER 不符合当前合法承诺组合 | 11 |
| 工具标记漏写 arguments | 9 |
| ACCEPT 携带不应存在的参数 | 3 |
| 调查工具当前不可用，仍调用 | 2 |
| 在响应阶段调用 PASS | 1 |

例如 Casey 调用 `INVESTIGATE(player="Casey", goal="Orchard")`，但注册工具目标仅允许 Alex、Blair。另一个重复错误是输出 `<tool_call>{"name":"PASS"}</tool_call>`，缺 `arguments:{}`；当前 Hermes 解析失败符合既定严格协议，没有自动补字段。OFFER 的例子是在已有 Cedar 绑定后仍提交双方 Cedar，而当前工具仅允许新增 Alex Maple。

有效执行动作：INVESTIGATE 99、PASS 104、OFFER 20、ACCEPT 19、REJECT 1。调查与 PASS 很多，仍需通过具体收益反事实判断调查价值，不能仅凭频率断言每次调查都无效。

按同一开局×玩家位置的四条轨迹统计：

| 组类别 | 位置组数 |
| --- | ---: |
| 四条均完整，utility 有差异 | 4 |
| 四条均完整，仅协议扣分不同 | 2 |
| 四条均完整，回报恒定 | 6 |
| 至少一条没有终局 utility | 16 |
| 合计 | 28 |

有 utility 差异的完整组仅来自 `cooperate_a-r2-s4` 和 `validation-2p-5`，每局两个玩家位置；其中只有前者属于 train。不能把后者算进训练信号。

失败整局不能直接当成“输了所以 utility=0”，也不应静默丢弃不完整组再宣称完整局通过率高。若以后训练需要覆盖失败分支，必须明确 episode 结束语义、受影响玩家回报和 loss mask；本轮没有改变规则。

## 性能

模型服务启动 207.15 秒（约 3 分 27 秒），不含下载。两卡各一个 TP=1 服务，graphs 均开启；GPU 0 对应服务日志记录模型加载占 3.2152 GiB、耗时 15.22 秒，CUDA graph 捕获约 20 秒、0.30 GiB；engine profile/KV/warmup 合计 61.34 秒。服务启动还包含其他初始化，不能把总时间都叫作权重读取。

两台服务启动明显不对称：GPU 7 的服务 04:14:30 启动 API，GPU 6 的服务到 04:16:26 才启动，相差约 116 秒。GPU 7 的模型加载仅 1.60 秒、engine warmup 19.45 秒；GPU 6 对应为 15.22 秒与 61.34 秒。差异跨越多个初始化阶段，说明单看模型体积无法解释全部等待；现有日志不能进一步确定是 I/O 缓存、进程调度还是其他资源差异，不据此直接归罪于 CUDA 版本或要求用户协调 CPU。

## 核验范围与后续

- 下载 bundle 全部文件 hash 通过；本地原数据源 hash 与抽样 manifest 一致；实际请求与冻结导出相同。
- 每题恰好 8 个独立 sample_index，无重复或 test；416 个独立 B/P seed 以及 289 个 self-play 调用 seed 与两台 vLLM 日志逐项匹配。奖励稳定不是由于客户端漏传 seed。
- 对 18 道 bridges 和 6 道简化 L0 重新运行 verify_task：独立 backward、原生收益、response certificate、旧 belief 和 posterior 均通过。原 B/P 28 题本轮核验数据与标签来源 hash、严格评分与映射，没有重新求解全部原 28 题；不扩大宣称标签审计范围。
- 当前采样文件仍 `gradient_ready=false`，不含可靠训练所需的完整 token IDs／行为 log-probs，不能直接喂 optimizer。

建议暂不启动大规模混训。混合比例不能凭空创造同组任务奖励差异；完整 self-play 训练组本轮只有很少 utility 信号，且失败回报分支尚未定义。

下一步可先讨论一次有明确边界的 1.7B 模式对照：复用少量失败／对照题与开局，比较当前 nonthinking 与 thinking，保持原生工具、1024 预算和二元任务奖励，检查解释、动作合法性及混合奖励组是否改善。它验证本次模型切换时的模式选择，不是默认改写全部游戏规则，也不是承诺 thinking 必然有效。若仍缺少可学习信号，再讨论明确的短 SFT 冷启动与直接 RL 的取舍；不偷偷改成冷启动。

通过后再决定 B/P 与真实 self-play 的混合更新比例，advantage 保持分任务、分组计算，避免长局 token 数隐式决定损失权重。
